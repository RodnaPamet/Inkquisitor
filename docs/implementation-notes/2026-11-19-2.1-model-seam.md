## Design

```
feature usecase (2.2 question engine, 2.5 enrichment, 2.6 research)
   │  its own permission check
   ▼
src/app-layer/usecases/model-calls.ts   callStructured(ctx, { template, data, schema, bookId, signal })
   │  binds the workspace's ledger
   ▼
src/lib/ai/call-structured.ts           the call, in order:
   1 build      prompt.ts: static system (cached) + task + nonce-fenced author data
   2 aborted?   → ABORTED, nothing sent
   3 AI_DISABLED=1 → KILLED, nothing sent
   4 guard in   guard/: injection scan per block — block → REFUSED_GUARD; flag → sent fenced, reviewRequired
   5 client     client.ts clientForRun — none → PROVIDER_ERROR (CREDENTIAL_NOT_CONFIGURED, …), nothing sent
   6 reserve    worst case (UTF-8 bytes + max_tokens at the dearest rates) vs the month — refused → CEILING
   7 send       client.messages.stream(…).finalMessage(), one deadline + the caller's AbortSignal
   8 validate   JSON → Zod; on failure ONE repair (re-reserved), then INVALID_OUTPUT
   9 guard out  egress scan — block → REFUSED_GUARD (answer withheld)
  10 settle     one AiCallLog row + cost into AiSpendMonth + reservation released, on every exit
   │
   ▼
src/app-layer/repositories/ai-call.repository.ts   (two short runInWorkspaceContext transactions)
   AiSpendReservation ── reserve: lock → sum(month) + sum(live reservations) + worst ≤ ceiling → upsert
   AiSpendMonth       ── settle:  lock → delete reservation → spent += cost → insert AiCallLog
   AiCallLog          ── append-only (trigger), numbers and names only (CHECKs)
```

**One seam to the SDK.** `src/lib/ai/client.ts` is the only file under `src/`
that loads `@anthropic-ai/*` (`local/anthropic-client-single-seam`, on since
0.4; the config test now also plants a construction at
`src/lib/ai/call-structured.ts`). A new client per call; the base URL, log
level, tracing (`metadata_only`, no propagation) and webhook key pinned; the
key passed explicitly (`authToken: null`), so the SDK reads no other
credential; `ANTHROPIC_CUSTOM_HEADERS` refused. Its messages-only middleware
is a deny-by-default allowlist: a POST to `/v1/messages` on the pinned origin
with no query string (`?beta=true` is the beta endpoint), no `anthropic-beta`
header, top-level body members from `PERMITTED_BODY_MEMBERS` only (so no
`thread` / `container` / `mcp_servers` / `context_management` / `metadata`, or
any member a later API version adds), `output_config` members `format` and
`effort` only, content blocks from `PERMITTED_CONTENT_BLOCK_TYPES` only in the
system prompt, every message and every tool result (no `document` or `image`,
whose `url` source is a fetch Anthropic makes and whose `file` source reads
the Files API; no `container_upload` or server-tool block), and no tool whose
type is not `custom` unless the client was built to allow that type — and every
type a client may ever allow is in `PERMITTED_SERVER_TOOL_TYPES`, which is
empty and typed `never`. The ESLint rule covers every module under `src/` and
`scripts/` (JavaScript too: `allowJs`), and `module.require` /
`createRequire(…)(…)` as loaders; a guard (`model-provider-host-single-seam`)
holds the provider's host name to the seam, so a plain `fetch` to the
Messages API cannot be written elsewhere. Subphase 2.6 adds the web search and web
fetch types there, in one reviewed line, and the research run asks for them by
name; every other client still allows none.

**Tiers.** A feature names `fast` / `balanced` / `deep`, never a model id
(`src/lib/ai/tiers.ts`): Claude Haiku 5.5, Sonnet 5.5 and Opus 5.5, each
overridable by `AI_MODEL_FAST` / `_BALANCED` / `_DEEP`. A tier also fixes
`max_tokens` (4 096 / 16 000 / 32 000), the call's hard deadline (60 s /
180 s / 600 s) and `output_config.effort` (low / medium / high). A template may
lower its output budget, never raise it.

**Prompts and the fence.** A template is declared with `definePrompt` (id,
version, purpose, tier, static `system`, static `task`, optional output budget
and guard mode) and frozen. The request builder takes no argument that reaches
the system prompt, and refuses one that contains a data block's text. Author
text goes only through `fenceData`: each block in
`<author_data_<nonce> label="…">…</author_data_<nonce>>`, with a 128-bit nonce
drawn per request (redrawn if it occurs in the data), stated at the top of the
user turn; the system prompt describes the convention without the nonce, so it
caches. Before fencing, ANY spelling of the tag stem (with or without a nonce,
spaced, hyphenated, any case) and the chat-template control tokens are
neutralised, so no block can close early or open another.

**Guard.** The scanners (normalize, patterns, injection, egress, policy) are
inflect's, logic unchanged, minus the `answer_steering` rule family. The
wrapper is new and pure: per-block input checks and an output check returning
rule ids, with no database, audit or remote provider. The mode is the
template's (`balanced` by default): an injection in author text is flagged and
the call proceeds with the text fenced ("flag and fence"; the result says
`reviewRequired`); `strict` blocks it; a secret in the answer is blocked in
every enforcing mode.

## Decisions

- **Structured output through `output_config.format`, with a single-tool
  fallback.** Every model family in the table — the three defaults included —
  is on the structured-outputs list (read 2026-11-19), so a call sends the
  output schema as `output_config.format`. The fallback the roadmap asked for
  (a single tool whose input schema is the output) is kept for a model id the
  table has no row for, and is NOT a forced `tool_choice`: Opus 5.5, Sonnet 5.5
  and the Fable 5.1 / 5.2 family refuse `any` / `tool` with a 400. It is
  `tool_choice: auto` with `disable_parallel_tool_use`, the task asking for
  exactly one call, and code checking it was made (a missing call is repaired
  like an invalid answer). The schema is built as the SDK's `zodOutputFormat`
  builds it (Zod's JSON schema through the SDK's `transformJSONSchema`) minus
  Zod's `$schema` member, which the transform would fold into the root
  description. `thinking` is never sent: the current models think adaptively
  by default and Opus 5.5 / Sonnet 5.5 refuse `disabled`; effort is the dial.
- **What the structured-output feature refuses is refused at build.**
  `jsonSchemaFor` checks the transformed schema (`assertStructuredOutputSchema`)
  and throws `AiPromptError` for a non-object root (the single-tool path makes
  it an `input_schema`, and which path a call takes depends on the deployment's
  model), an object with arbitrary keys (`z.record`: the API requires
  `additionalProperties: false`, so the SDK's transform would turn it into
  `{}`), a recursive schema or an external `$ref`, and more than the documented
  24 optional or 16 union parameters — each otherwise a 400 on every call, or
  a schema quietly emptied.
- **The JSON schema must stay code.** Anthropic caches a compiled schema for up
  to 24 hours outside the zero-retention scope (prompts and outputs are not
  stored). No schema may be built from author text (an enum of an author's
  values, say); the 2.2 prompt that first tempts this must not.
- **The repair.** One repair, after the first answer fails JSON parsing or the
  Zod schema: the first request is re-sent unchanged (same system, same fenced
  user turn, same nonce), the model's own answer is appended as the assistant
  turn (thinking blocks passed back unchanged: an append-only edit, as preserved
  thinking requires), then one user turn listing the problems by path, code and
  Zod's message. No author text beyond the first request's. On the single-tool
  path the problems go back as an error `tool_result`. A truncated answer
  (`max_tokens`) is not repaired; a model refusal (`stop_reason: refusal`) ends
  the call PROVIDER_ERROR `MODEL_REFUSED`.
- **Stops and empty answers.** `refusal` is MODEL_REFUSED; `max_tokens` and
  `model_context_window_exceeded` are TRUNCATED; any other stop that is not an
  answer's (`end_turn`, or `tool_use` on the tool path) is NO_OUTPUT; none is
  repaired. An empty answer IS repaired, but its empty text block is not passed
  back (the API refuses an empty assistant turn that is not the last): the
  repair asks again after the first request's own turns. Twice no answer is
  NO_OUTPUT.
- **The guard fails closed, and is recorded.** A scanner that throws refuses
  the call (nothing sent; or the answer withheld) as REFUSED_GUARD
  GUARD_UNAVAILABLE. A throw that is neither ours nor the SDK's (a ledger
  failure, a bug) is recorded PROVIDER_ERROR INTERNAL_ERROR, never as a
  provider connection failure. A block's LABEL is scanned with its text: it is
  code-shaped but sent outside the fence, and a caller may build it from an
  author's words (a slug). The fence's stem is matched over a folded view of
  the text (invisible characters dropped, NFKC, the guard's homoglyph fold and
  bracket and slash look-alikes), and only the matched stretches of the
  original are replaced. The task and the output schema are checked for a
  block's text as the system prompt is.
- **One deadline.** The tier's `timeoutMs` bounds the whole call — both
  attempts and the SDK's two retries — through one `AbortController`, combined
  with the caller's `AbortSignal` (`AbortSignal.any`). The deadline's abort is
  TIMEOUT, the caller's ABORTED (an outcome added to the roadmap's list so a
  cancelled call never reads as a slow provider). A call that stops mid-stream
  is charged what the stream reported (`message_start` carries the input
  usage); one that stops before any usage was reported is charged its input's
  worst case and marked `costEstimated`. An attempt the caller cancelled (or
  the deadline passed) before it left is not sent and not charged.
- **Ceiling concurrency: an advisory lock AND a reservation row.** Before a
  call, one short transaction takes `pg_advisory_xact_lock(hashtext('ai-spend:'
  || workspaceId))`, sums the month's settled spend and the live reservations,
  and inserts this call's worst case as a reservation only if the total fits.
  Settlement takes the same lock, deletes the reservation, adds the real cost
  to the month and appends the record. A lock alone would have to be held
  across the model call (a pooled connection and an open transaction pinned to
  a network call for minutes); a reservation row alone does not stop two checks
  reading the same sum at once. Under READ COMMITTED (what
  `runInWorkspaceContext` uses) each statement after the lock sees the
  previous holder's committed reservation, so of concurrent calls only those
  whose worst cases fit together are admitted — the integration test holds two
  calls in flight and sees the other four refused, unsent. A repair re-reserves
  the call's row (first attempt's real cost plus the repair's worst case).
- **Reservations expire.** A reservation counts until its call's deadline plus
  60 s; a process that dies mid-call stops holding budget then, and the
  workspace's next reservation deletes rows a day past expiry. The cost of such
  a call is not counted — the price of not leaking budget forever.
- **The month's spend is its own table.** `AiSpendMonth` holds a workspace's
  settled spend per UTC calendar month (a call is charged to the month it
  started in). The ceiling does not sum `AiCallLog`, because the book's purge
  deletes the book's call records by cascade (the task's requirement) and must
  not lower the month.
- **The ceiling default is a placeholder.** `AI_MONTHLY_CEILING_USD_DEFAULT`
  defaults to $25 per workspace per month; the owner may change it. A
  malformed value reads as the default (never wider) and production refuses to
  start with it. No per-workspace override column: it would have no writer yet;
  a later billing phase adds one with its UI.
- **The worst case is an upper bound, not an estimate.** Input: the UTF-8 byte
  count of the serialised request (no token is shorter than a byte) plus 4 096
  tokens for framing and the API's structured-output instructions, priced at
  the dearer of input and cache-write rates (Haiku 5.5's long-prompt row when
  the bound passes 100 000). Output: `max_tokens` at the output rate. An
  unknown model is priced at the dearest rate of every column.
- **Prompt caching of the system prompt only.** The system block carries
  `cache_control: ephemeral` (5 minutes; zero-retention eligible). A system
  prompt under the model's 512-token minimum is simply not cached, at no cost;
  the repair attempt re-reads the cached prefix. Author text is never in a
  cached breakpoint of its own.
- **Zero data retention is an organization arrangement, not a header.**
  Anthropic enables ZDR per organization through its account team; no request
  member asks for it. Code does what it can: the middleware refuses every
  surface ZDR does not cover (Batches, Files, message threads, containers,
  MCP, server tools, any beta header) — under ZDR those are not blocked, they
  just leave the arrangement — and production refuses to start holding
  `ANTHROPIC_API_KEY` without `ANTHROPIC_ZDR_CONFIRMED=1`, the operator's
  statement that the key's organization has the arrangement (`clientForRun`
  refuses again in production). The statement is an operator step: confirm the
  contract with Anthropic before setting it. The Fable / Mythos models are
  Covered Models (30-day retention required, no ZDR): a tier override naming
  one fails at the API under a ZDR organization.
- **`ANTHROPIC_API_KEY` is optional, and not required in production yet.**
  Nothing calls a model in production before the question engine (2.2), which
  adds the key to `aiConfigProblems`. Without it every call ends
  PROVIDER_ERROR `CREDENTIAL_NOT_CONFIGURED`, recorded, nothing sent.
- **The kill switch is the environment only.** `AI_DISABLED=1` refuses every
  call (KILLED), checked first in `callStructured` and again in `clientForRun`.
  No runtime flag: a database or Redis flag would add a read to every call and
  a write path nobody owns yet; restarting with the variable is the operator's
  lever.
- **`AiCallLog` is append-only, with three exceptions.** A trigger refuses
  UPDATE, DELETE and TRUNCATE for every role, except the workspace's cascade,
  the book's cascade (its purge) and the clearing of `requestedById` when that
  person is deleted; app_user holds SELECT and INSERT only. Every string column
  is bounded by a CHECK (purpose, prompt id and version, model, output mode, an
  error code from the closed list, rule ids), so a sentence cannot be stored by
  mistake. `outcome` and `errorCode` are tied: OK and REPAIRED carry no code,
  everything else one.
- **Retention.** There is no data-retention document yet. `AiCallLog` holds no
  author text and is kept for the life of its workspace (and of its book, for a
  book's calls), as the audit trail is; `AiSpendMonth` for the life of the
  workspace; `AiSpendReservation` rows are deleted on settlement or a day past
  expiry. A retention policy for call records (e.g. 13 months) is a later
  decision, and must then delete through a path the trigger admits.
- **The guard's mode is the template's.** Inflect reads a per-tenant mode from
  the database and audits every non-clean verdict; here the mode is code a
  reviewer reads, and the verdict's rule ids are on the call record. The
  `answer_steering` family is not carried: it fires on "choose a …" and
  "answer …", which is ordinary author prose. The false-positive rate of the
  remaining rules on real answers (`act as`, `use the tool … with`) is
  measured in 2.H; under `balanced` they flag, never block.
- **Typed errors carry no text.** Each is an `AppError` with a reason from
  `AI_ERROR_CODES` and the call id; Zod issues keep path and code only
  (a Zod message can quote the value it judged); provider errors keep status
  and type, never the provider's message. Log lines carry the call id, codes,
  token counts and money.
- **No test reaches a network.** The SDK is handed a fake `fetch` through
  `clientForRun`'s test seam: real SSE streams, HTTP errors, a stream that
  hangs until aborted, and a stream held until a gate opens (the concurrency
  test). `jest.setup.js` already clears `ANTHROPIC_API_KEY`; the tests set a
  fake one.
