# 2026-11-19 — 2.3 Dials, personas and pack mounting

**Commit:** uncommitted (branch `wip/2.3`, stacked on `wip/2.2`, PR #34)

The three interview dials — depth, detail and manner — with workspace and book
defaults; several personas per session (Stanford STORM's perspective idea,
MIT, credited in `NOTICE`); and the interview packs mounted through the skill
mount system lifted from inflect-compliance (`5528464`): a load-time text
scan, an evaluation record per pack, a content hash pinned on the session at
start (written once) and compared before every round. The design is the
staged `design/QUESTION-ENGINE.md` (sections 4.2, 4.4 and 8) and `FORMAT.md`
(sections 1.10, 3, 4, 6 and Appendix B). Owner decisions of 2026-11-19 shape
two parts: **D11** (production mounts a pack only on a real model's record)
and the **Evals** workflow (real-model records are made in GitHub Actions).

## Design

```
POST …/interviews { scope, …, depth?, detail?, personaKeys?, offerRecommended?, preferChoice? }
  resolveDials(session > BookInterviewDefaults > WorkspaceInterviewDefaults > CODE_DEFAULT_DIALS)   per dial
  packNamesFor(kinds in scope, personas)  →  packMounts(registry, mode, names)                      lazily, cached
        mode = packRecordModeOf(NODE_ENV): production → model, otherwise → structural              (D11)
        verdict per pack: text scan → record present → replay the record through produceRound
                          → graded against evals.json → mode allows the record's kind?
  pinsFor → refusal: 503 PACKS_NOT_MOUNTABLE { packs: [{ name, reason }] }, nothing written
          → InterviewSession.packPins (write-once trigger) + dials + budgets, audit with dialSources

claim (every round)   … stop decisions (2.2) … assertModelAvailable
                      pinMismatch(session pins, packs the round mounts, this request's registry)
                        PACK_NOT_MOUNTABLE → 503, nothing written
                        PACK_CHANGED / PACK_NOT_PINNED → session PAUSED, stopReason PACK_CHANGED
produceRound          one call per persona with a share (round-robin, lead rotates by round)
                      each call: its craft packs + its persona pack in the system prompt,
                      version `question-generation.2.3.0+packs.<12 hex of the packs' hashes>`
                      metrics.calls[]: persona, version, packs, cost budget, cost, call id, outcome
                      questions tagged with the persona (view: personaKey, personaName)
                      picks-first order when every persona asks for it (Gentle Mentor)
```

**A dial changes prompts and budgets only.** `dialEffects` is the whole list:
levels in reach and rounds (depth); round cap, question kinds, answer bound,
output tokens (detail); one generation call per persona and the token budget
(manner); the two toggles' sentences. Nothing a dial touches is on the
bible's write path, and that is held by structure:
`tests/guards/dials-stay-off-the-bible-write-path.test.ts` finds every module
that imports the versioned save's writers (`writeFieldValues`,
`recordVersion` from `bible-common.ts`) — the bible usecases now, 2.5's
acceptance later — and refuses any dial or pack module in their import graph,
value or type. A pack shapes wording only: the frontier is code's, and the
formats forbid a pack instruction that changes scope (the two fixed bullets).

## Decisions

- **The mount gate (D11, owner decision 2026-11-19).** Production mounts a pack
  only on a REAL MODEL's evaluation record; development and test also accept a
  STRUCTURAL record (made by the deterministic structural generator). There is
  no override: no environment variable lets production mount a structural
  record (an explicit "records pending" flag was built first and removed on
  the decision). Until real-model records are committed, production refuses
  every interview with 503 `PACKS_NOT_MOUNTABLE` naming each pack and its
  reason (`STRUCTURAL_RECORD_REFUSED`), writes nothing, and logs at every
  start `[startup] WARN: 21 of 21 interview packs cannot mount (…)`. The rest
  of the product runs. A pack with no record, or with a record that does not
  pass, is refused everywhere.
- **A record is graded by replay.** Inflect's records hold an answer per case
  and grade it by phrases. Ours hold each generation call's RAW output; the
  grader runs the case through `produceRound` with a generator that returns
  those outputs, so the evaluation measures the engine the product runs and a
  hand-edited record is graded on what it now says. Code grades: the expected
  frontier reached by a generated question (or nothing asked), no question on
  another core key, and no `mustNot` behaviour the engine had to prevent.
  Story content, prose, leading wording and a persona's tone are listed as
  UNGRADED per case: a judge grades them in 2.H. The bar is every case
  (`PACK_EVAL_PASS_RATE = 1`), to be argued down with real-model evidence.
- **A record is tied to its pack, its set and the prompt.** It names the pack's
  content hash, the set's hash (a persona's set includes `situations.json`),
  and `QUESTION_PROMPT_VERSION`; a change to any of them is a refusal until
  `npm run packs:evaluate` is re-run (structural) or the workflow is (model).
  A unit test also holds every committed structural record equal to what the
  generator produces today. A persona's record does not pin the craft packs it
  ran beside (as inflect's skill records do not pin their siblings).
- **Evaluation runs use core fields and no challenges**, matching the formats'
  frontier rules (1.9): a case expecting an empty frontier expects no question.
- **The prompt version names its packs per call** (rule 9):
  `question-generation.2.3.0+packs.<12 hex>` over each pack's name, version and
  content hash, within 2.1's 64-character version shape; `AiCallLog` records
  it, and the round's `metrics.calls` lists the packs behind each digest with
  the call's cost budget and cost. The per-call cost budget stays the
  template's ($0.25, 2.2).
- **Pins.** A JSON column on the session (`packPins`), not the design's
  `SessionPackPin` table: written once, read whole, and the write-once trigger
  is inflect's `mountedSkills` one. NULL means "predates pinning" (a 2.2
  session); such a session, or a pack it never pinned, pauses `PACK_CHANGED`
  with `stopDetail.problem` `PACK_NOT_PINNED`. A changed pack pauses rather than
  ends the session: the pins cannot move, but a deployment that restores the
  file lets it resume (tested). A pack unchanged but no longer mountable is a
  503 with nothing written: a deployment condition.
- **What a session pins**: the craft pack of each kind in scope — every kind
  for a BOOK session, since a book may gain an element of a new kind mid-session
  — and each persona's pack.
- **Defaults are two tables** (`WorkspaceInterviewDefaults` keyed by workspace,
  `BookInterviewDefaults` keyed by book), each dial a nullable column ("pass
  it on"); personas a JSON array (`[]` is a setting: no persona). Replaced
  whole by PUT. **Permissions:** reading is `bible.view`; writing either layer
  is `bible.edit`, because a default only changes how the next interviews are
  asked and whoever may run an interview already chooses every dial; a
  workspace setting that CONSTRAINED editors would be `workspace.manage`, and
  none does.
- **Personas: zero to three** (design 8.3: one call each per round), in the
  author's order; the first leads round 1 and the lead rotates. Zero is kept
  (2.2's sessions ran with none): the craft pack alone words the questions.
- **Picks first** (design 4.4) is on only when every persona of the session is
  in `PICKS_FIRST_PERSONAS` (the Gentle Mentor): within one element, scale,
  either-or, choice, open, scenario; elements keep their frontier order.
- **Mount verdicts are lazy and cached** per registry, mode and pack: a full
  replay of all 21 sets takes about two seconds, so a request checks only the
  packs it would mount; production's start-up report warms them all.
- **`ANTHROPIC_WORKSPACE_ID`** (lifted from inflect): the repository's key is
  organisation-level, which Anthropic refuses without the
  `anthropic-workspace-id` header. `clientForRun` sends it when set.
- **The STORM credit** is in `NOTICE`; the copyright line is read from the
  project's LICENSE.

## Evals

Real-model evaluation records are made by the **Evals** workflow
(`.github/workflows/evals.yml`), never in a development sandbox.

1. Make the secret available: repository **Settings → Secrets and variables →
   Actions**, secret `ANTHROPIC_API_KEY`; for an organisation-level key, the
   repository **variable** `ANTHROPIC_WORKSPACE_ID` too.
2. **Actions → Evals → Run workflow**, from `main` (or the branch whose packs
   are to be recorded), with `packs` (`all`, `none`, or names such as
   `craft-character,persona-socratic`), `coverage` (also run the ten-concept
   coverage set) and `budget_usd` (default 5, at most 25).
3. The job skips with a notice when the secret is absent. Otherwise it builds
   the pgvector Postgres, migrates, and runs
   `npm run packs:evaluate -- --generator model --out evals-out`: the
   product's wired generator over 2.1's `callStructured` (guard, fence,
   ledger), in a throwaway workspace whose monthly ceiling is the budget, so
   the run cannot spend past it. The summary table is in the step summary.
4. Download the artifact `pack-evaluation-records`. Review each record (its
   `generator.kind` is `model`, its `promptVersion` and hashes are current;
   the summary says which cases failed). Copy each
   `evals-out/<group>/<dir>/evaluation-record.json` over the structural one at
   `src/lib/interview/packs/<group>/<dir>/evaluation-record.json` and open a
   pull request. CI's tests check every committed record the way the gate
   does; a model record that does not pass does not mount.
5. When every pack has a passing model record on `main`, production mounts
   them and interviews come on. The tests that hold committed records equal to
   the structural generator's output compare only records whose
   `generator.kind` is `structural`; the test asserting that production mounts
   no shipped pack is the one that pull request updates.

The workflow holds `contents: read`, pushes and commits nothing, is dispatch
only and is not a CI check.
