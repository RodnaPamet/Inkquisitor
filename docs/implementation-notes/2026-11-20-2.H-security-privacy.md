## Design

### The prompt-injection suite (item 1, item 9)

```
src/lib/redteam/injection-corpus.json   24 cases: ANSWER, ELEMENT_TEXT, IMPORTED_NOTE, RESEARCH_PAGE, ATTACHED_FILE
        │                               × IGNORE_PREVIOUS, PROMPT_DISCLOSURE, SCOPE_ESCAPE, CROSS_BOOK, ROLE_CHANGE,
        │                                 FORGED_FENCE, ENCODED, NON_ENGLISH, INVISIBLE_CHARS, EXFIL, TOOL_USE, FALSE_APPROVAL
        ▼
src/lib/redteam/injection-suite.ts      each case placed where the product would put it, run through the
                                        product's OWN step (runReconcileStep / produceRound / runResearchSteps)
                                        over the seams it is handed; judged on what is SHOWN or STORED:
                                        SCOPE · DISCLOSURE · CROSS_BOOK · INSTRUCTION · TOOLS
        │
        ├── tests/unit/redteam/injection-suite.test.ts    a COMPROMISED fake model (obeys every injection,
        │                                                 knows everything) over the real callStructured:
        │                                                 every property holds whatever the model does
        ├── tests/integration/injection-suite.test.ts     the real usecases, two books in one workspace:
        │                                                 nothing of the other book is ever sent; a server tool
        │                                                 beyond the two web tools stops the run
        └── scripts/injection-redteam.ts + .github/workflows/injection-redteam.yml
                                                          the REAL model, nightly (garak's place): report artifact
```

The deterministic suite does not trust the model at all: the fake answers
every step with out-of-scope proposals and questions, its own system prompt,
the other book's canary and a copy of the instruction, schema-valid so that
validation (not the parser) is what refuses them. A case passes only if code
refused all of it. CROSS_BOOK is judged where it means something: on what is
stored (grounding refuses what the sources do not hold) and on what the
product wrote into a request (the system prompt and user turns; the model's
own turn passed back in a repair is the model's words, not a read).
INSTRUCTION is D14's contract on storage: nothing the guard reads as an
injection and nothing that addresses the product is stored unflagged.

**Disclosure is now refused by code.** The graders counted
DISCLOSES_INSTRUCTIONS, but nothing refused it, so a model talked into
reciting its instructions had them shown or stored. `disclosesInstructions`
(`src/lib/text/prompt-disclosure.ts`: eight consecutive words of the step's own
static system or task text, or any spelling of the fence's tag) is asked by
the question round (a new drop reason `DISCLOSES_INSTRUCTIONS`), by
enrichment's `copiesInjectedText` and by research's `carriesInjectedText`
(both refusing `COPIES_INJECTED_TEXT`). Every reference wording of every
evaluation set still passes.

**The nightly** is carved from inflect's `garak.yml`: the skip without a key,
a repository variable that keeps the scheduled run off until the owner
switches it on (`INJECTION_REDTEAM_ENABLED`, inflect's `GARAK_ENABLED`), a
budget (default $2, at most $10, as the throwaway workspace's ceiling) and
"a night that probed nothing is not a pass" (exit 1 when no case reached the
model). It keeps `evals.yml`'s properties: one secret, `contents: read`,
artifacts only, no push and, unlike garak.yml, no auto-issue; not a check.
The research gather is not run live: the fake web stands in, as in the
evaluations.

### Privacy (item 6)

`tests/integration/privacy-sinks.test.ts` plants one marker word in every
kind of author text — book title and logline, element name, summary and
fields, a relation note, a concept note, answers, reconcile proposals, a
rephrase, a research brief, an attached file, a fetched page and its
findings, a model answer that fails validation, an unexpected error whose
message carries it, a `?q=` in a failing request's URL — and reads every sink:
log lines (as handed to the logger and as the redacting formatter writes
them), spans (an in-memory OpenTelemetry exporter), Sentry (the SDK mocked:
the error handed over, scope tags and user), every `AiCallLog` column and
every audit row's details. Each sink is first shown to hold its own words,
then not the marker.

Sentry's `redactUrl` now cuts every query string and fragment (#29 item 1):
the relation picker sends fragments of element names as `q`. Breadcrumb
`url` / `from` / `to` and a URL-shaped breadcrumb message are cut too.

Zero retention (item 6, second half): what can be configured is listed in
`docs/sub-processors.md` ("Zero-retention settings, as configured") with the
code that holds each. New: under `AI_RETENTION_MODE=zdr` a tier override must
name a ZDR-eligible family (`ZDR_ELIGIBLE`; the Fable family is a Covered
Model), or production refuses to start (#30 item 6). D5's `standard-beta`
mode is unchanged.

## Decisions

- **The suite judges outputs, not the model.** A real model refusing an
  injection proves little about the next model; a compromised fake model that
  the code still contains proves the containment. The nightly measures the
  composed system on top.
- **The nightly is off until the owner switches it on.** Inflect's owner
  made the same call for garak (a scheduled job that spends money every
  night). Dispatch always runs. Owner item: set `INJECTION_REDTEAM_ENABLED`.
- **Disclosure is refused at eight words of the static system and task
  text**, not six (the graders' measure) and not the per-round system (which
  holds pack guidance and examples a good question legitimately echoes). The
  prompts describe what an answer should say — the fit prompt asks for "a
  short rationale: how the finding bears on this entry" — so six words of a
  faithful answer can be the prompt's own; the D13 stub's rationale was one,
  and was refused until the run was lengthened. A recitation runs longer.
- **Polarity is a heuristic, clause by clause.** Clauses break at
  punctuation and contrasting conjunctions, and a negation covers the words
  after it in its clause, so "a custom, not a law" and "darkness, and people
  could not see" keep their right halves. A negation spelt as a word
  ("distrusts") is not seen; the evaluation records still pass. Idioms whose
  negator negates nothing ("not only", "not just", "no doubt", "no matter")
  are not read as negations. An UPDATE's stored value is a PRIOR, not
  evidence: a clause that restates mostly an answer clause (half its content
  words or more) keeps that clause's polarity even where the stored value
  said the opposite, so the reversal an answer asks for is not refused
  because the stored clause shares more words (found in review).
- **REMOVE is grounded by the question, not the text.** An answer is about a
  field when it answered a question targeting that field; a retraction rarely
  repeats the value it retracts, so lexical grounding would refuse the right
  answer.
- **A name lock, not a unique index.** Names compare by `nameKey` (look-alikes,
  a leading article), which the database cannot compute, and a manual create
  may legitimately repeat a name; what must not happen is a check racing a
  create, which the lock rules out.
- **A deletion time is pinned only for app_user**, matching
  `superuser_bypass`'s trust model, which keeps the tests' backdating and an
  operator's repair possible.
- **Retention deletes outside row-level security, by role.** A session GUC
  would not do: app_user can set any custom GUC. The floor is in the trigger.
  The 400-day default is conservative (a year-on-year month always has both
  months); the policy is an owner decision.
- **PDF fetches are refused, and the slack is reserved once, not per
  sampling.** Reserving a context window per sampling iteration ($20+ a
  request) would refuse research outright under a $50 month; aborting at the
  first non-text result bounds a PDF to the one sampling already in flight.
- **`dedupeKey` keeps its deployment-wide key.** The question round computes
  and compares dedupe keys in the pure core, outside any workspace context,
  and the exact-repeat index holds every stored key: moving it needs the
  workspace id threaded through `produceRound`'s text context and a rekey of
  stored keys, in the subsystem the other half of 2.H is changing for
  repetition. The derivation (`workspaceSubkey`) is in; the vector content
  hash uses it.
- **Rekey path (designed, not built).** A job per workspace, in its own
  context: page through `Question` (decrypting through the workspace's DEK),
  recompute `dedupeKey` under `workspaceSubkey('inkquisitor-question-dedupe-key/2', workspaceId)`
  and the vectors' `contentHash` (or rebuild the revision, which refiles every
  vector), writing in bounded batches; run after a master-key rotation too,
  since both rest on the master key. Deriving from the workspace DEK instead
  would survive a master-key rotation, at the cost of the DEK being reachable
  from the pure core.
