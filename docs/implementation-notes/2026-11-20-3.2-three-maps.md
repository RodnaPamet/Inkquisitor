# 2026-11-20 — 3.2 The three maps

**Subphase:** Phase 3.2 (roadmap section 4), owner decision D22 (with D1, D18, D20).

The relationship map, the plot board and the timeline, built on 3.1's canvas
platform. Rows stay the source of truth; where the bible owns an order or an
act, the map only derives position from it.

## Design

```
relationship map   CHARACTER, FACTION nodes; free positions (MapNode x/y/w/h, lane NULL)
plot board         PLOT_BEAT cards; lane = the beat's `act` field, place in lane = its rank
timeline           TIMELINE_EVENT cards; x = its rank along the axis, label = `story_time`;
                   one lane per character taking part (`takes_part_in`), a mark under each event

drag a card ──► installCardDrop (operation complete, not pointing) ──► dropTarget(layout, …)
            ──► POST …/elements/:id/order {baseVersion, after, before, act?}
            ──► moveElementInOrder: lockOrder(book, kind) → element lock → assertBaseVersion
                → placeRank(others, {after, before}) → setOrderRank (+ act field) → recordVersion(movedInOrder)
            ──► GET map (refresh) ──► deriveLaneLayout ──► placeCards (mergeRemoteChanges: no edit, no undo step)

arrow between two nodes with no relation to draw ──► onNeedsRelation ──► RelationTypePicker
            ──► POST …/relations (the template's own end) ──► drawRelationEdge ──► autosave
edge line deleted (its nodes stay) ──► onEdgeRemoved ──► useToastWithUndo:
            commit = save the map without the edge, THEN DELETE …/relations/:id; undo = redraw it
double-click / "Open an element" ──► ElementSheet (FieldEditor + useElementAutosave) ──► refresh
element page ──► loadElementPage reads the maps drawing its kind ──► StoryMapPreview (SVG, no tldraw)
```

**The story order** (`src/lib/bible/story-order.ts`). A rank is the digits of a
base-36 fraction (`0-9a-z`, never ending in `0`, at most 64 characters), so ranks
compare as strings in code-unit order and there is always room between two. A
move computes ONE key strictly between the neighbours the author saw — and,
because a plot board lane shows one act while the order is global per kind,
also between `after` and the very next rank of the whole order — so the key is
unique without reading anyone's act. The unique `(bookId, kind, orderRank)`
(NULLs distinct) is the guarantee; the order's advisory lock makes two moves
queue so each reads the other's rank. NULL is "not placed yet": a new element
starts unplaced, so creation needed no change and pre-3.2 events were not
back-filled with an order nobody stated.

**Derived positions are the server's too.** `saveStoryMap` and a restore store
the positions `deriveLaneLayout` gives (whatever the request carried), and the
map view hands the canvas those positions; on a derived map a node's move or
resize is not a map edit (`classifyTldrawStoreDiff`'s `derivedPositions`), and a
lane card cannot be resized (`canResize` reads `lane === null`). So the map
never holds a second opinion about an order the bible keeps; its rows record
membership, edges and freeform, and its positions are a cache of the bible.

**Lanes and the bible.**

| map | lane (MapNode.lane) | position | bible fields read |
|---|---|---|---|
| relationship | NULL | the author's (x, y, w, h) | none |
| plot board | the `act` option value, or `no-act` | column of the act; row = rank order in the lane, unplaced after placed | `act` field, `orderRank` |
| timeline | `placed` / `unplaced` | column = rank order; the unplaced after one empty slot | `orderRank`, `story_time` (label), `takes_part_in` relations (character lanes) |

## Decisions

- **PLOT_BEAT straight after PLOT.** The kind order decides which template
  declares a relation (the earlier one). After PLOT, a beat declares its own
  relations to characters, factions, settings, events and objects; only the
  beat's plotline (`has_beat` / "beat of") is declared on PLOT. Before PLOT
  would have spared PLOT's template but put "Plot beat" above "Plot" on the
  board and in the PDF. The causal types (`causes`, `enables` "makes possible",
  `sets_up` / "pays off", `undoes`) and the act labels (Opening, Escalation,
  Crisis, Resolution) are original, neutral words.
- **One deploy.** No row holds `PLOT_BEAT` until code that knows it writes one,
  as with `RESEARCH`, `PACK_CHANGED` and `REPHRASE` before it. The value is
  added in a migration of its own because the next one's CHECK names it (it
  compares `kind::text`, so it would also hold in one transaction). The
  residual risk: during a rolling deploy, an old container reading a book
  where a new one has just written a beat fails that read. There is no rolling
  deploy before Phase 7; its runbook must take a new enum value in two steps
  (readers first, then writers). Owner: worth a line in the Phase 7 launch
  checklist.
- **Lanes from `takes_part_in`, not `participants`.** A relation names an
  element by id: it survives a rename, is what 4.2's continuity checks can read,
  and is typed. The `participants` list is free text ("the twins", "a crowd")
  that cannot be resolved to characters without guessing, and a guess on a
  timeline reads as a fact. The list stays as the interview's prose. The type is
  declared on CHARACTER (it precedes TIMELINE_EVENT in the kind order): "takes
  part in" / "involves". `related_to` makes no lane: it says nothing about
  taking part.
- **A card sits on the axis, not in a character's lane.** A node draws an
  element once, so an event with three people in it is one card and three
  marks, one in each person's lane, drawn behind the cards (`LaneBackdrop`,
  tldraw's `OnTheCanvas`, from React state: never a store record, never saved,
  never selectable).
- **A reorder writes a version, one per moved element.** The order is a bible
  fact (4.2 reads before and after from it), and every save of an element writes
  exactly one version. A fractional rank means a drag changes ONE row, so it is
  one version, not one per shifted neighbour. The version is marked
  `movedInOrder` (a column, as `restoredFromVersion` is) because the change
  summary holds only the author's words; its snapshot carries the rank
  (written only for a placed element, so every existing snapshot serialises as
  before). A RESTORE keeps the element's place: the rank an old snapshot names
  sits among neighbours that may have moved, been deleted or taken it.
- **Fractional ranks over integers.** Integer positions rewrite every element
  after the drop on each drag (many versions, and a write conflict for every
  concurrent editor of the same order). A rank costs one string per element and
  grows about one character every five inserts into one gap; a gap split past
  64 characters is refused `ORDER_RANK_EXHAUSTED`, never cut (moving a
  neighbour reopens it). A rebalance was not built: it would rewrite the order.
- **Unplaced is honest.** An event or beat is unplaced until the author places
  it; the timeline shows the unplaced in their own zone ("Not placed yet") and
  the first drag onto the axis places one. Creation order was not taken as story
  order.
- **The canvas's moves are remote changes.** Putting cards where the bible says
  (`placeCards`) and refreshing what they show (`showNodes`) run in
  `mergeRemoteChanges`: no autosave, no undo step, no drop report.
- **Removing an edge removes the relation, on every map.** An edge draws a
  relation; a picture without it while the bible keeps it would redraw on the
  next arrow. The commit first saves the map without the edge, so the deletion's
  cascade does not move this tab's version (D20) and its next save is not
  refused; an edge put back meanwhile (tldraw's own undo) keeps the relation.
  Removing a NODE still only takes the element off the map.
- **The embedded view is an SVG, not tldraw.** Positions are already in the
  view (stored, or derived by the server), so the element pages keep tldraw out
  of every route's first load (`check-build.js`) and every node is a plain link
  for keyboard and screen readers.
- **Kinds per map are enforced on the server** (`KIND_NOT_ON_MAP`, with the
  allowed kinds). A map 3.1 saved with another kind shows without it
  (`excludedNodes` says how many) and its next save or a restore leaves it out.
- **Keyboard equivalents.** The element sheet's "Earlier" / "Later"
  (`stepMove`) move an element one place by keyboard; "Open an element" in the
  toolbar opens any node's sheet without the mouse; the picker is a radio group.
  3.H owns the full list-view equivalent of every canvas action.
- **Export loses the lanes.** tldraw's export draws shapes only, and the lanes
  are not shapes; an exported timeline shows the cards in order without the
  character lanes (3.H, if wanted).
- **Two things found in a real browser.** tldraw's select tool turns a
  double-click on a shape that cannot be edited into a new text shape; a story
  node answers the double-click itself (`onDoubleClick` returns an unchanged
  "change") and the host opens the sheet from the editor's event. And tldraw's
  own z-indexes put its toolbar over a dialog opened above the canvas; the
  canvas surface is `isolate`, so they stay inside it.
- **PLOT_BEAT and word search (3.4).** The search reads every element of every
  kind and every template field (it iterates `BIBLE_KINDS` and the templates),
  so beats are searchable with no list to extend; `stakes_shift` is a scale and
  is skipped like every scale.
