## Design

```
fact layer            resolve: live facts read BY CLAIM KEY first, then by subject (≤ LIVE_FACTS_READ_MAX)
                      a fact's own version never gives it provenance (a re-run writes nothing)
                      a refused piece yields nothing; the run goes on; the version is still the baseline (DONE)
source ingestion      every chunk read + embedding failed → STOPPED PARTIAL EMBEDDING_FAILED → resume = re-embed only
                      upload: the book re-checked FOR SHARE in the write's own transaction
parse worker          heap read unanswered ≥ MEMORY_STALL_MS → read the process's RSS (from `online`) instead
nightly continuity    dispatch for ONE night (nightKey; discovery + partial unique index)
                      page failed (over budget / never valid) × 3 nights → passed over, counted, shown
                      page: factsCut (last run), parkedSubjects, complete (only when neither and a pass finished)
questioning           holds re-read at persist; the repetition gate probes the slot's beat (pendingIn);
                      ladder history paged, cut named (historyCut) → no ladder/pair question that round
                      decide-later pair names the pair; composite (workspaceId, id) keys for the two id-only FKs
startup               every D11 gate's report (GATE_REPORTS) → one [startup] WARN line each
```

## Decisions

- **The claim key is read first, not mapped from the unique violation.** A
  `P2002` mapped to "already held" after the fact would leave the run's
  transaction aborted (PostgreSQL refuses every later statement), so the insert
  could not then add the provenance. Reading the version's own claim keys
  (`listLiveByKeys`, bounded by the keys: one live fact per key) before the
  resolve finds every held claim whatever the subject's size. The subject read
  past `LIVE_FACTS_READ_MAX` still bounds the RULE contradictions and
  NO_LONGER_STATED, which is 4.H-b's scale question.
- **A re-run must write nothing, and it did write once.** The new idempotency
  test found that re-running a version gave each fact the version had itself
  stated a provenance row naming that same version (the fact is held by its own
  key on the second pass). The resolve now skips a held fact whose own version
  is the one being extracted.
- **A refused piece moves the baseline (#60 item 2).** Of the two designs in the
  issue — record refused section hashes, or move the baseline past refused
  sections — the second needs no schema: a refused call yields nothing for its
  piece, the run continues with the others, and the version ends DONE, so the
  next version's changed sections are measured from it and the refused text is
  sent again only once it changes. A version every call of which was refused is
  DONE with outcome GUARD_REFUSED / REPEATS_PROMPT (counted `refusedCalls`,
  `refusedSections`). What the refused text stated is never extracted, which was
  already GUARD_REFUSED's meaning ("it yields no fact").
- **#60 item 3 was already fixed by 4.2.** `settleAllForFact` settles the
  proposals where the invalidated fact is the newer (INVALIDATED_NEWER) as well
  as the older; `tests/integration/continuity.test.ts` ("Keep the newer") holds
  it. Nothing changed here.
- **An embedding-only resume costs nothing and asks the same gates.** The
  resume of an EMBEDDING_FAILED source confirms a zero "at most" and makes no
  model call, but it goes through the ordinary dispatch (model available, D11
  record), so there is one path to run a source. "No provider configured" is not
  a failure (a deployment without one stays lexical), only a provider that
  answered with a failure is.
- **The parse watchdog's residual window is documented, not closed.** A worker
  held in one native call cannot answer a heap read, and it cannot be terminated
  either until the call returns; the parent now reads the process's resident
  memory while a read is stalled. Allocation inside one poll (or one stall) is
  still not stopped; the readers are pure JavaScript decoders over bounded input
  (`readZip`'s caps, the 20 MB upload), so no single allocation is unbounded.
  An OS limit (a child process under an rlimit) would close it, at the cost of a
  process per file; not built.
- **One night is a key, not a time window.** A wall-clock spacing would have
  had to agree with the schedule, the stale-run expiry and every test that runs
  several nights in a row. A night key (the UTC date twelve hours before the
  dispatch) is what "a second dispatch in one night" means, and a partial unique
  index holds it for two dispatches at once. Tests that simulate nights name each
  night (`nextTestNight`).
- **A page fails "for good" only for reasons it causes.** CALL_OVER_BUDGET and
  an answer never valid (INVALID_OUTPUT, PROMPT_INVALID) count; a timeout or a
  provider outage does not (three bad nights of an outage would otherwise pass
  pages over). Three nights in a row (`CONTINUITY_PAGE_FAILURES_MAX`), then the
  cursor moves past the page, its subjects counted on the check and shown on
  the page; a new pass starts the count again, and the last pass's count stays
  shown until then.
- **A cut is read from the last run, not stored on the check.** Every run of a
  pass reads the same `CONTINUITY_FACTS_READ_MAX`, so the last finished run's
  `factsCut` says whether the book is past it; no column. The page's `complete`
  joins it with the parked count and the pass state, and the outcome OK is worded
  "the pass finished, but not every fact was checked" when it is not complete.
- **A slot's beat is held to its own session.** The database probe for a
  question about the beat not yet created matches the same session's earlier
  questions about it (`aboutPending` under the slot's anchor). Another session's
  beat after the same anchor is another beat, and holding the two to each other
  would block the beat questions of every later gap after that element.
- **A cut history silences the ladder for that round.** A layer in the unread
  part of the history cannot be proved unanswered, so the conservative reading
  of rule 5 is to ask nothing from the ladder or the pairs while the cut binds
  (named in the round's plan, `historyCut`). The ceiling is 20,000 rows, read a
  thousand at a time.
- **Composite keys with `SET NULL (col)`.** PostgreSQL 15+ sets only the named
  column; Prisma cannot spell it and refuses `SetNull` over a required field, so
  the schema says `NoAction` and the migration carries the real action (the
  database is what acts; the client never emulates).
- **#63's remaining note** (compaction headroom for "until I stop") was built in
  4.4 (`compactionReserveTokens`).
