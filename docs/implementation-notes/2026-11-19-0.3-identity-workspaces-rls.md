# 2026-11-19 — 0.3 Identity, workspaces and data isolation

## Design

Phase 0.3 adds authentication and tenancy on top of 0.4's platform services,
lifting inflect-compliance's patterns at commit
`5528464fc54a8681956f3b9ce23ca9c075f0420e`, re-keyed from tenants to
workspaces (owner decision D4).

```
browser ─▶ src/middleware.ts (edge)
             ├─ rate-limit tiers (0.4), charged first, keyed on the JWT's userId
             └─ workspace gate: /w/<slug>/**, /api/w/<slug>/** need <slug> in the
                JWT's memberships[] (every spelling of the path; capped at 50,
                truncated → defer). No session → /login | 401; not a member →
                /no-workspace | 403.
        ─▶ /api/auth/[...nextauth]   next-auth 4 (src/auth.ts)
             Credentials → authenticateWithPassword (bcrypt over sha256, progressive
                           lockout per email, one compare on every failure path)
             Google      → resolveGoogleSignIn (only email_verified; link / claim / provision)
             jwt         sign-in: membership claims + recordNewSession + USER_SIGNED_IN
                         later:   verifySession → throw SessionRevokedError
             signOut     revoke the session row + USER_SIGNED_OUT
        ─▶ /api/auth/register        signUpWithPassword (policy, HIBP, hash) →
                                     provisionAccountWithWorkspace (ONE transaction)
        ─▶ /api/w/<slug>/…           withApiErrorHandling(requirePermission(key, h))
             getWorkspaceCtx: session → DB membership → WorkspaceRequestContext
             assertPermission: AUTHZ_DENIED audit row, then a generic 403
             usecase → runInWorkspaceContext (SET LOCAL ROLE app_user,
                       app.workspace_id) → repositories
        ─▶ /w/<slug>/ pages          layout: getCurrentWorkspace(slug) → WorkspaceProvider
```

- **Schema.** `enums.prisma` (`WorkspaceRole`), `auth.prisma` (User, Account,
  VerificationToken, UserSession), `workspace.prisma` (Workspace with
  `encryptedDek` / `previousEncryptedDek`, WorkspaceMembership) and
  `audit.prisma` (AuditLog). One migration, created with `prisma migrate`,
  carries the RLS SQL: the `app_user` role and grants, FORCE RLS, one
  `workspace_isolation` policy per scoped table (USING and WITH CHECK), the
  `superuser_bypass` policy, the append-only trigger on AuditLog, and no
  app_user grant on Account, UserSession or VerificationToken.
- **RLS at run time.** `runInWorkspaceContext` opens a transaction as
  `app_user` with `app.workspace_id` set, so every policy bites;
  `runWithoutRls` is the logged bypass with a closed reason list; the tripwire
  logs a scoped query made outside both. Sign-up is the one flow that switches
  role mid-transaction (`bindWorkspaceInTransaction`): it creates the user and
  the workspace as the owning role, then writes the membership and the audit
  rows as app_user.
- **Sign-up.** User + workspace (with its data key, `createWorkspaceWithDek`)
  + OWNER membership + USER_SIGNED_UP / WORKSPACE_CREATED / MEMBERSHIP_CREATED
  commit together or not at all. Google provisioning shares the path.
- **Sessions.** One `UserSession` row per sign-in; the JWT carries its id. The
  `jwt` callback reads the row and the user's `sessionVersion` in one query on
  every pass and throws for a revoked, expired or missing row or a bumped
  version, so `getServerSession` returns null. Settings lists the person's
  sessions and signs out one or all the others (undo-toast convention).
- **Field encryption.** Lifted whole and wired into `src/lib/db.ts`: the
  manifest is empty (Phase 1 fills it); a manifest field is `v2:` under the
  workspace key inside a context and `v1:` under the master KEK outside one.
  `DATA_ENCRYPTION_KEY` and `AUTH_SECRET` are required in production (env
  schema and start-up checks); the sentinel runs at web and worker start-up.
- **Audit.** `logEvent(ctx, …)` appends to a per-workspace hash chain under an
  advisory lock; user-level events (sign-in success and failure, sign-out,
  session revocation, Google link/claim) go to each of the user's workspaces.

## Decisions

- **No Prisma adapter.** inflect uses `@next-auth/prisma-adapter`; with JWT
  sessions its only job would be creating users and accounts, which the
  sign-up usecase already does in the transaction that also creates the
  workspace. One writer, so there is never a user without a workspace.
- **One isolation policy per table, not inflect's split insert sibling.** A
  second permissive policy is OR'd with the first; with one policy holding
  both USING and WITH CHECK there is nothing to widen it.
- **The middleware charges the rate-limit tier before the gate.** inflect
  gates first so an unauthorized request gets the cheaper answer; here a
  refused request still spends its budget, so probing slugs is counted, and a
  crafted sign-in path one of whose spellings names a workspace stays in the
  auth tier (the 0.4 crafted-path suite holds that).
- **The gate collects a slug from every spelling** (per-segment decoded, fully
  decoded, dot-resolved) and admits only when every candidate is held. Over-
  refusing a crafted spelling costs nothing; under-refusing one would be a
  bypass of the pre-filter.
- **Session verification fails closed on a missing row and open on a database
  error.** A missing row means the token is not one we minted (or its row was
  deleted); a database blip must not make NextAuth clear every cookie. A
  sign-in whose session row cannot be written fails.
- **One bcrypt compare per failure, measured by count.** Inflect pays two
  compares (its migration probe); with no legacy hashes Inkquisitor pays one
  everywhere, and the integration test counts compares rather than timing.
- **User-level auth events go to every workspace the user belongs to** (up to
  the claim cap). A workspace's owner sees who signed in to reach it; a failure
  for an unknown email has no workspace and is logged without the address.
- **Sign-out is next-auth's POST with its CSRF token** (`/signout` is a page
  with a button, not a GET), and `events.signOut` revokes the row.
- **The palette reads the slug from the URL.** It is mounted in the root
  providers, above the workspace layout's provider; only an admitted page
  renders under `/w/<slug>/`, so the URL slug is one the viewer belongs to.
- **Membership claims refresh at sign-in and on a session update only.** The
  App Router cannot re-write the cookie from a server render, so a membership
  granted later reaches the edge at the next sign-in; the DB-backed server gate
  is authoritative meanwhile. Fine while sign-up is the only membership writer;
  invitations (later) need a refresh path.
- **Deviations from the brief.** Password reset was not lifted (the brief made
  it optional; no mail flow exists yet), so there is no PasswordResetToken.
  inflect's Upstash-backed per-email credential window was not carried; the
  progressive lockout is per process, behind the edge auth tier and the
  route's `LOGIN_LIMIT`. Last-OWNER protection is enforced in the usecase under
  an advisory lock, without inflect's database trigger. The encryption round
  trip is proved against a test manifest over `User.name` (no workspace-scoped
  model has a text column yet), not a test-only model.
- **E2E runs with the rate limiter off and no breach check**
  (`playwright.config.ts`): every spec signs up from one address within a
  minute. The tiers are proved by the unit and integration suites.
