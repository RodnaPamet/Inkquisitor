# 2026-11-18 — 0.1 Repository bootstrap

## Design

The application skeleton of Phase 0.1: a Next.js 16 App Router app with a home
page, a root layout and `GET /api/health`, on the toolchain inflect-compliance
uses (Node 24, React 19, TypeScript strict, Tailwind 4, Prisma 7 with a schema
folder, Jest 30, Playwright, ESLint 9 flat config), plus the licence files, the
local service stack, the image pattern and the four required CI checks.

```
src/app/layout.tsx, page.tsx      home page (product name + one-line description, Tailwind utilities)
src/app/api/health/route.ts       liveness: 200 {status:'ok'}, no-store, no dependency checks
src/lib/product.ts                the name and description, shared by page and metadata
src/env.ts / src/env-client.ts    @t3-oss/env-nextjs: NODE_ENV + DATABASE_URL / no client vars yet
src/lib/db.ts                     PrismaClient over @prisma/adapter-pg
prisma.config.ts, prisma/schema/  CLI config + base.prisma (generator, datasource; no models)
tests/unit, tests/guards          Jest "unit" project — no DB, no network
tests/integration                 Jest "integration" project — real PostgreSQL
tests/e2e                         Playwright against `next start` on :3100
```

The dependency set is what the skeleton uses and nothing more: next, react,
react-dom, zod, `@t3-oss/env-nextjs`, `@prisma/client`, `@prisma/adapter-pg`
and `prisma` at run time; the toolchain as dev dependencies. Versions are
inflect-compliance's ranges at the carve commit (`next` exact-pinned as there).

## Decisions

- **LICENSE is inflect's byte for byte outside the Parameters block**, and a
  unit test pins the header and the Terms by SHA-256 to inflect's bytes at the
  carve commit. BUSL's Covenant 4 forbids modifying the licence other than its
  parameters, so drift there is a legal defect, not a style one.
- **`prisma generate` is the postinstall step.** Typecheck, tests and build all
  need the generated client, and a step every CI job and every developer must
  remember is a step somebody forgets. The cost is that the Dockerfile copies
  `prisma/` and `prisma.config.ts` before `npm ci`; inflect has the same
  ordering lesson for `patches/`.
- **The schema has no models.** Prisma 7 generates a client from a datasource
  alone, which is enough for `$queryRaw`; the first models (users, workspaces)
  belong to 0.3 with their RLS policies, and adding them here would mean
  tables without RLS, against D4.
- **`src/lib/db.ts` exists although no route reads a table.** It is what the
  integration smoke test exercises (the adapter really connects), and it gives
  `DATABASE_URL` a real reader in `src/env.ts`. `/api/health` does not touch
  the database: it is a liveness probe, and the readiness probe that pings
  Postgres and Redis is a 0.4 item.
- **The integration project fails, never skips, without a database.**
  `jest.setup.js` falls back to a documented `inkquisitor_test` URL on
  `localhost:5432` (the CI service's coordinates) and never to `.env`, which
  names the development database that later integration tests would write to.
- **`next.config.mjs`, not `.ts`.** The runtime image prunes dev dependencies,
  TypeScript among them, and `next start` loads the config file.
- **`next build --webpack`**, as inflect: the strict CSP of 0.H needs the
  nonce on dynamically loaded chunks, which Turbopack's runtime does not set.
  The build passes with or without `SKIP_ENV_VALIDATION`, because nothing in
  the build graph reads `env.DATABASE_URL`; CI sets it anyway so a future
  server module evaluated at build time cannot make the build need a secret.
- **CI uses `postgres:16`, not inflect's pgvector image**, as the brief says;
  pgvector is first needed in Phase 4.1, and the local compose stack already
  carries it. CI runs the integration project in the Test job too, since the
  service is there.
- **No `workspaces` field.** No workspace package exists yet; 0.2 adds
  `packages/ui` and the field with it.
- **`repo-files.ts` lifted early** (it is listed under 0.4): the client-env
  guard needs a file population, and the brief's own rule is that a guard's
  population comes from git.
- **Tests were mutation-checked by hand**: editing one character of the BUSL
  Terms, dropping a variable from `.env.example` and renaming the Test job each
  turn the matching suite red.
- **E2E is not a CI job yet.** The brief names exactly four jobs. The Playwright
  suite was run locally against the system Chrome (the Playwright browser
  download is blocked in this environment) and passes; it checks the heading's
  computed size and weight, which is the "Tailwind visibly applied" property.
