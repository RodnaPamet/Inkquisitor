# 2026-11-20 — 3.1 Canvas platform carve

**Subphase:** Phase 3.1 (roadmap section 4), owner decisions D1, D6, D18 and D19.

The tldraw canvas platform carved from inflect-compliance's process canvas
(`src/components/processes/**`, `src/lib/processes/**`, commit
`5528464fc54a8681956f3b9ce23ca9c075f0420e`), with the compliance taxonomy,
controls, automation modes, agent flow, drill scopes, presence, rules and
checkpoints left behind. Rows stay the source of truth; tldraw is a view.
3.2 builds the three real maps on it; 3.1 mounts a minimal page that works.

## Design

```
page  /w/:slug/books/:bookId/maps/:kind           (server: loadStoryMapPage)
  └─ StoryMapWorkspace          header; NO tldraw import
       └─ CanvasErrorBoundary
            └─ next/dynamic(StoryMapEditor, { ssr: false })   ← tldraw arrives here
                 ├─ AddElementPicker · Arrange · CanvasExportMenu · History · Save
                 ├─ MapConflictNotice                 (a refused save)
                 ├─ StoryMapCanvas  ── tldraw ── StoryNode / StoryEdge shape utils,
                 │                                StoryEdge binding util,
                 │                                arrow-to-edge, one-node-per-element
                 ├─ CanvasHistorySidebar  (Sheet)  → snapshots, restore
                 └─ CanvasDiffOverlay     (Modal)  → computeCanvasDiff

autosave: store listener → classifyTldrawDiff → markDirty → (debounce) →
          serializeEditorCanvas → tldrawToRows → PUT …/maps/:kind {expectedVersion,…}

server:   saveStoryMap — bible.edit → sanitise freeform → structure checks →
          [tx] requireBook → advisory lock (book, kind) → version check (409) →
          references in the book → no-op? → create | conditional bump →
          replace nodes, edges → MapSnapshot → STORY_MAP_SAVED
```

**Rows.** `StoryMap` (one per book and kind, decision D18), `MapNode` (one
BibleElement drawn: `x`, `y`, `w`, `h`, `lane`), `MapEdge` (one BibleRelation
drawn), `MapSnapshot` (the save's canonical state, append-only). An element
appears on a map once and a relation once, so the element and relation ids are
the canvas's keys: a node's shape id is `createShapeId(elementId)`, an edge's
binding `binding:<relationId>`. The book travels in every foreign key
(`(workspaceId, bookId, mapId)`, `(bookId, bibleElementId)`,
`(bookId, bibleRelationId)`), so the database refuses a node or edge drawing
another book's element or relation; BibleRelation gained the `(bookId, id)` key
for it.

**The round trip.** `tldrawToRows(rowsToTldraw(rows)) === rows`, held by the
ported tests and, in jsdom, through a live store. What a node SHOWS (the
element's name, kind label and completeness badge) and an edge's label come in
beside the rows (`MapDisplay`), resolved by the host from the bible, and never
go back out: renaming is a bible edit. `canvas-changes-tldraw.ts` compares only
the persisted props, so a refreshed badge is not an edit.

**The version lock.** Every save names `expectedVersion` (0 for a map nobody
saved). Under the advisory lock on (book, kind) a different current version is
a 409 `VERSION_CONFLICT` with `currentVersion`, nothing written; the
conditional bump is the second line. The client stops autosaving on a 409 and
shows `MapConflictNotice`: Reload (this tab's edits are lost, and it says so)
or save these edits over the newer version (an explicit choice, never a retry).
A save whose canonical state equals the stored one writes nothing.

**Edges come from drawing.** An arrow bound at both ends to nodes becomes an
edge when the book holds a relation between the two elements (the first not yet
drawn, running the relation's own way); with none, the arrow stays and the
author is told the elements are not related yet (3.2 adds the picker that
creates a relation).

## Decisions

- **One map of each kind per book (D18), created on its first save.** Lazy
  creation keeps every read a read (a READER opening a map writes nothing),
  needs no backfill for existing books and no change to book creation or the
  bundle import. The unique (bookId, kind) is the guarantee; the advisory lock
  on (book, kind) serialises a map's first save with every other, so two tabs'
  first saves end in one map and a 409, never a unique-violation 500.
- **dagre only (D18).** elkjs (EPL-2.0) and the force-directed layout are not
  carried; `@dagrejs/dagre` is an MIT npm dependency, so NOTICE carries nothing
  for it (nothing is ported or vendored).
- **Deleting an element or relation cascades** to its nodes and edges: the map
  is a picture of the bible, and blocking the deletion would send the author
  hunting through three maps first. A trigger bumps the map's version when a
  node or edge goes because its element or relation went (told apart from the
  map's own save by the vanished parent; `pg_trigger_depth()` reads 1 in a
  cascade, measured), so an open tab is refused 409 rather than drawing the
  deleted node back. The version moves ONCE per deletion (a transaction-local
  marker per map: a node and its edges are one version), and the deletion
  writes that version's snapshot (decision D20: history never skips a
  version). The snapshot is encrypted, which a trigger cannot do, so
  `deleteElement` and `removeRelation` take every map lock of the book
  BEFORE the delete (`lockMapsForBibleDeletion`) and write the moved maps'
  snapshots after it (`recordMapsAfterBibleDeletion`, `fromBibleDeletion`,
  attributed to the person deleting); a deferred constraint trigger refuses,
  at commit, a map left at a version with no snapshot, whoever deletes.
  Taking the map locks first also means a deletion and a save never wait on
  each other's rows: before it, a save that had deleted a map's nodes and a
  deletion holding the element's row could deadlock (the save's re-insert
  waited on the element, the cascade on the save's deleted node). A restore
  leaves out (and counts, `dropped`) what the bible no longer holds.
- **Resize is persisted.** inflect's process node locked resize because its row
  had no size; the MapNode row has `w`/`h`, so resize is on, bounded to what
  the save accepts.
- **The freeform layer is author text** (sticky notes): encrypted
  (`StoryMap.freeformJson`, and the snapshot that copies it), bounded,
  shape-checked (a record of the canvas's own types is refused: it would be
  restored on top of the real one), free of prototype keys at any depth, and
  every string leaf sanitised as plain text without trimming
  (`sanitiseFreeformForStorage`). Nodes and edges carry no text.
- **No CDN.** tldraw loads its fonts, icons and translation from
  `cdn.tldraw.com` by default; the CSP refuses that origin, and each load would
  tell a third party who reads which map. `@tldraw/assets` (same release, same
  licence) is served by `/api/canvas-assets/<version>/…` from an allowlist of
  paths, cached immutably. tldraw waits for every embed icon to decode before
  showing anything, so those are served too although embeds are off. The
  locale is pinned to English (D12) on ONE user object for the component's
  life: a user rebuilt per render re-ran tldraw's translation load forever,
  measured in a real browser as an editor stuck on its spinner (the E2E spec's
  toolbar wait is what catches it; jsdom does not reproduce it). A pasted link
  becomes plain text: a bookmark would unfurl through tldraw's service.
- **The watermark stays (D1).** No licence key is read or set, nothing names
  the watermark's class; a guard scans the tree, and the E2E spec sees the
  watermark on the map page.
- **TipTap override.** tldraw 3.15.6 (the last 3.x) depends on TipTap 2, and
  GHSA-cp6q-959q-f8rh (moderate, `mergeAttributes` and own `__proto__` keys)
  has no fix on TipTap 2, so `npm audit --omit=dev --audit-level=moderate`
  failed on the bare install. `package.json` overrides move tldraw's and
  `@tldraw/editor`'s TipTap dependencies onto the root's 3.x line. Checked,
  not assumed: typecheck, the jsdom mount, and an E2E spec that types a sticky
  note, saves it and reads it back after a reload. The freeform sanitiser also
  refuses `__proto__` keys, so the advisory's input cannot be stored whatever
  editor reads it.
- **Two client modules per canvas surface.** `StoryMapWorkspace` imports no
  tldraw; `StoryMapEditor` (everything that needs the editor) is the dynamic
  chunk. `scripts/check-build.js` reads every page's client reference manifest
  and fails a build that puts tldraw's script or stylesheet in any route's
  first load, the map page's included (3.H adds the size budget).
- **Element kinds are not restricted per map in 3.1.** Any element of the book
  can be a node on any map; 3.2 decides which kinds each map takes.
- **Permissions.** `bible.view` reads a map and its history; `bible.edit`
  saves and restores — the canvas and the bible are one dataset, so no new
  keys.

## Owner decisions (D20)

- **The watermark-track request is allowed, and nothing else of tldraw's
  CDN.** In production (https), tldraw's licence manager, unlicensed, `fetch`es
  `https://cdn.tldraw.com/<version>/watermarks/watermark-track.svg` once the
  editor mounts (a fetch, so `connect-src`; the watermark itself is a data URL).
  The CSP now admits exactly that URL, by its full path, in `connect-src` only
  (`TLDRAW_WATERMARK_TRACK_URL`, `src/lib/security/csp.ts`);
  `tests/unit/security/csp.test.ts` derives it from the installed
  `@tldraw/editor`, so a release that moves it fails there. tldraw receives the
  visitor's IP address and the product's domain name, no author text
  (`docs/sub-processors.md`).
- **The TipTap override stays.** It is a security-driven deviation from
  tldraw's declared dependency range, kept because GHSA-cp6q-959q-f8rh has no
  TipTap 2 fix and tldraw 3.x (D1) declares TipTap 2. It and the tldraw
  major-version guard move together: `tests/guards/tldraw-tiptap-override.test.ts`
  fails when a TipTap package in the lockfile leaves major 3, when a TipTap
  dependency tldraw or `@tldraw/editor` declares is not overridden onto the 3.x
  line, and when the installed tldraw stops declaring TipTap 2 (the reason is
  gone: remove the override with the tldraw move). Under it, TipTap 3's
  StarterKit carries Link, Underline, ListKeymap and TrailingNode, and tldraw
  adds its own Link, so the canvas hands tldraw its list with those four off
  (`STORY_TEXT_OPTIONS`, `src/components/canvas/tldraw/rich-text-extensions.ts`;
  before it every note editor carried two link extensions). The sticky-note E2E
  (`tests/e2e/story-map.spec.ts`: type a note, save, reload, read it back) is
  the override's proof in a browser.
- **A bible deletion that removes map content writes a snapshot** (see
  "Deleting an element or relation cascades" above).

## Review fixes

- **A freeform record never carries a row's id.** tldraw's create APIs put,
  so a freeform record named `shape:<elementId>`, `shape:edge-<relationId>` or
  `binding:<relationId>` replaced the node, line or binding on load (and the
  edges bound to a replaced node made every save throw). The save and the
  restore refuse one (`FREEFORM_REFUSED`, `RESERVED_ID`, `assertFreeformIdsFree`),
  and `restoreFreeform` skips a record whose id the rows already hold.
- **Deleting an edge's line deletes the edge** (`installEdgeLineRemovesEdge`):
  the line is the only selectable part of an edge, and its binding used to stay
  behind, saved and redrawn on reload.
- **The boundary's "Try again" loads the chunk again.** `next/dynamic` makes
  one `React.lazy`, and a rejected lazy stays rejected, so the editor's dynamic
  component is made per mount (`DynamicStoryMapEditor`) and the boundary's
  remount asks for the chunk afresh.
- **Autosave counts edits** rather than comparing timestamps: an edit in the
  millisecond a save started compared equal and was never saved.
