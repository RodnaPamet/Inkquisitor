# 2026-11-26 — 4.4 Continuous, deep questioning (D23, D30)

## Design

The frontier (2.2) stops being THE question engine and becomes one of five
**generators**. Each proposes **candidates**: a subject's field to ask about (or,
for a source question, a fact to decide), with a **value score** and — unless the
model words it — its question already worded by code. Code then validates,
deduplicates and orders every candidate, whichever generator proposed it, best
value first, and cuts the round to its room.

```
loadInterviewState ──► frontier (2.2, rule 5 applied)
        │                         │
        └─► loadGeneratorInputs ──┤  ladder history · facts held · pairs · pending source facts · continuity items
                                  ▼
                       generateCandidates (pure)   FRONTIER · LADDER · RELATIONS · SOURCES · CONTINUITY
                                  ▼
                       selectCandidates (pure)     validate → one per field / fact / basis → value order → cut
                                  │                (only above MINOR_VALUE_FLOOR; nothing above it: VALUE_FELL)
                                  ▼
                       planRound (2.2)             persona deal + challenge over the model-worded ones
                                  ▼
             claim ──► tie-break (fast call, D11)  reorders only the first run of near-equal candidates
                                  ▼
                       produceRound                model words the frontier; code-worded ones join for dedupe and order
                                  ▼
                       persist                     stillAskable per generator, then THE HARD REPETITION GATE
```

| Generator | Proposes | Worded by | Lands in |
|---|---|---|---|
| FRONTIER | every open field on the frontier | the model (QUESTION_PROMPT, unchanged) and the pack fallback | the field (reconcile ADD) |
| LADDER | the next unheld layer (WHAT → WHY → COST → WHO_KNOWS → BREAKS → EDGE_CASES) of an answered prose field | code | the same field (reconcile UPDATE/ADD) |
| RELATIONS | a KIND/BOOK session's relations between scope elements (their empty fields, model-worded) and pairs of characters/factions with no relation yet | the model / code | the relation's fields; a pair's answer may become a NEW_RELATION |
| SOURCES | a PENDING, unflagged fact of `bookSourceSet` about a scope element | code, quoting it, yes/no | the fact: confirmed or rejected at the round's close |
| CONTINUITY | pending CONTRADICTED proposals, OPEN threads, timeline gaps | code | the field the facts disagree about, the thread's landing field, `story_time` |

Value scores (`value.ts`, 0..100) are code's: frontier core 70 / optional 45
(+dependants, −level), sources 90 into an empty field / 35 into a filled one,
contradiction 85, gap 65, thread 55, ladder 60 − 9 a layer (+8 core, −10 a held
fact), pair 50/50/40. Below `MINOR_VALUE_FLOOR` (30) a candidate is minor.

Session length is the author's: ROUNDS (1..30), QUESTIONS (1..300) or
UNTIL_STOPPED; depth now sets how far DOWN (levels and ladder layers), never how
many rounds. Stops: QUESTION_BUDGET and SESSION_LIMIT complete; VALUE_FELL pauses
(last in the precedence) and the author's `goOn` resumes it for good.

## Decisions

- **Code words the four new generators' questions.** QUESTION_PROMPT is
  unchanged (its 33 pack records stand). A source question must quote its source
  verbatim (D23's own example), a contradiction both facts' own words; a template
  over what the book holds invents nothing (D3) and needs no call. The cost: no
  persona voice on a follow-up or a pair. Moving them into the model's wording is
  an open decision for the owner.
- **The ladder lands in the field it follows up.** D23's "questions only fill
  template fields" holds: a layer's answer deepens the same prose field through
  reconcile (UPDATE when stored, ADD while only answered in session). No layer
  column on the bible. A layer is "held" — rule 5 — when an answer to it is
  ANSWERED anywhere in the book, or it was asked in this session; a layer waits
  for the one above. Choice, scale and list fields are not followed up.
- **A source question's decision is made when its round closes**, from the
  latest revision of its answer, so changing yes to no before finishing the
  round changes the decision. Only a fact still pending and unflagged is decided
  (`decide`'s `onlyPending`): the interview never overrides the author's own
  decision on the Facts page, and a decision there clears `decidedByAnswerId`.
- **A source question whose predicate answers no field targets none** (the
  owner's own example, an ability, maps to no field): the targets CHECK admits
  zero targets for SOURCES alone; reconcile never reads one, and only a "yes" to
  a fact that answers a field counts on the frontier.
- **Pairs are characters and factions** (who want things of each other), at most
  `PAIR_CANDIDATES_MAX` considered and `PAIRS_PER_ROUND_MAX` asked a round; a
  KIND/BOOK session's existing relations become subjects only when it pinned the
  relations pack at start (a pre-4.4 session never did, and a subject whose pack
  it never pinned would pause it PACK_CHANGED).
- **Threads land only where a field tracks them** (`THREAD_LANDING_FIELDS`: a
  plot's setups and payoffs, a beat's open threads, a custom entry's or a
  research note's open questions); a thread about any other kind is not asked.
- **The tie-break reorders the round, not its membership.** The plan (and so
  which candidates a round holds) is fixed at the claim; the call reorders the
  round's first run of near-equal candidates, so the highest-value ones are asked
  FIRST. It accepts only an exact permutation of the numbers shown.
- **A round of code-worded questions alone makes no model call**, so the kill
  switch and the monthly ceiling do not pause it (as the frontier's own stop
  never needed the model).
- **The repetition gate is code under a book-level lock**, not a unique index:
  existing rows may hold repeats from before the gate, and a rephrase legitimately
  replaces its original. Both writers of questions take `lockBookQuestions` after
  the session's lock.
- **Session bounds**: `SESSION_QUESTIONS_MAX` 480 (one session's read) and a
  SESSION_LIMIT stop one worst round before it; an open-ended session's token
  budget is sized for 30 rounds.
- **A question budget is the budget's stop, not the frontier's.** A QUESTIONS session
  whose budget is spent plans an empty round because it has no room, not because
  nothing is left: `stopNow` reads FRONTIER_EMPTY only when no candidate is left
  above the floor (`selection.remaining`), so the session ends QUESTION_BUDGET.
- **Code-worded questions are their own group on the session page**
  (`CODE_WORDED_GROUP`): no persona asked them, and "From the craft guidance"
  (the pack fallback's heading) would misname them. A panel's persona groups are
  unchanged.
- **A finished round's "N changes proposed" notice stays beside the next round**:
  before 4.4 a short session usually ended with the round that proposed them;
  now follow-ups keep it going, and the notice must not vanish with the stream.
- **The evaluation workflow's ten inputs are full**: the tie-break's set runs
  with `book_level`.

## Trade-offs and open items

- Follow-ups, pairs and continuity questions are code-worded (above).
- A follow-up answered while the first answer's proposal is still pending may
  produce a second ADD on the same field; accepting the first makes the second
  stale (409 PROPOSAL_STALE), as with any two proposals on one field.
- A series fact asked in one book's interview is decided for every book that
  draws on it, exactly as deciding it on that book's Facts page is.
