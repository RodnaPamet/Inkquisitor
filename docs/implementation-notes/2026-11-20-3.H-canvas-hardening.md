# 2026-11-20 — 3.H Hardening the canvas

**Subphase:** Phase 3.H (roadmap section 4), the canvas half: items 1 to 7 of
the hardening brief and issue #45 (the 3.1 follow-ups), under D1, D18, D20,
D22 and D24. The other half (the bible, story order, search and the interview
follow-ups) lands beside it.

## Design

```
round trip     seeded random graphs ──► rows → tldraw → rows (pure; five cycles)
               ──► canonical state ⇄ JSON         ──► each derived layout (again: nothing moves)
               ──► a live tldraw store (jsdom)    every one IDENTICAL

arrange        toolbar ──► runAutoLayout (async) ──► layoutOffMainThread(job)
                   job: ids, positions, sizes, direction   (no author text)
                   Worker? ──► auto-layout-worker.ts (dagre) ──► positions ──► one updateShapes (one undo step)
                   none / fails / wrong id ──► the same computeAutoLayout on the main thread
               the worker's chunk `story-map-layout`: whole (next.config.mjs), on demand (check-build)

list view      Canvas | List toggle ──► StoryMapListView (no tldraw; plain data, callbacks)
                   reads the LIVE store; acts through the editor's own handlers
                   ──► the same autosave, version lock and rows

history        GET …/snapshots[?before=v] ──► a page of SNAPSHOT_PAGE_SIZE, nextBefore
restore        pending edits? ──► confirmation says so ──► saveNow ──► restore at the version it reached

database       BEFORE INSERT MapSnapshot: version = the map's current version (every role)
               map_bump_once_for_cascade: ONE setting `inkquisitor.map_cascade` = "<txid>:,id,id,"

build          check-build.js: … + the layout worker on demand and self-contained
                               + per-route first load (gzipped JS + CSS) ≤ scripts/bundle-budget.json
```

## Decisions

- **No new dependency for the property tests.** fast-check is in the tree only
  as a dependency of a dependency (`effect`), so a seeded generator
  (mulberry32) is written in `tests/helpers/random-graph.ts`: the same graphs
  on every machine, a failure named by its seed. The generator's own test
  asserts it reaches every case the contract is about (no lane and a lane,
  negative fractions, the coordinate bound, both directions between a pair,
  freeform), so the property cannot pass over nothing.
- **Work is counted, never timed.** The serializer's duplicate check built a
  set of every OTHER edge for each edge (2.25 million adds at 1,500 edges);
  it now counts each relation once, and the test reads `Set.prototype.add`
  calls and their growth from half to full size. Deleting every edge used to
  scan the whole store per line; the test counts `store.allRecords` calls. On
  the server, `pg.Client.prototype.query` calls for a save and a view are the
  same at 500 nodes as at 50, on each of the three maps: no per-node query.
  The indexes are the 3.1 ones, already held by `schema-index-coverage`.
- **A binding's id is the relation's, always.** Edges loaded from rows always
  had `binding:<relationId>`; edges drawn on the canvas got a random id, which
  is what forced a store scan to find them. `drawRelationEdge` now gives the
  same id, and refuses to draw a relation already drawn (it has that id).
- **The worker is made per job and terminated after it.** Nothing outlives a
  layout; a worker's start-up is small next to a layout of the full map. The
  job carries ids, numbers and a direction (the test pins the keys), and a
  reply is matched by id, so a stray message is never taken for the answer.
  Where no `Worker` exists, the worker cannot start, posts `failed`, or errors,
  the same pure function runs on the main thread: a layout the author asked
  for is never refused. The canvas stays live while the worker works, and a
  node removed meanwhile is not written back.
- **The worker must be one chunk, and that took a config change.** A
  dedicated worker runs under the policy of its own response, and every
  `/_next/static/` response carries `default-src 'none'` (0.H). The first build
  split dagre — shared with the main-thread fallback — into a chunk the worker
  `importScripts`. `next.config.mjs` now leaves the chunk named
  `story-map-layout` out of Next's client splitting, and `check-build.js`
  fails a worker chunk that loads another script, as well as the worker in
  any route's first load. The arrange E2E runs it in Chromium under that
  policy and reads `data-layout-thread="worker"`.
- **The bundle budget is per route, gzipped, recorded with 10 % headroom.**
  First load is the root chunks (`build-manifest.json`'s `rootMainFiles`) plus
  the route's client chunks and entry stylesheets from its client reference
  manifest, each file once, gzipped at level 9 (the file's size, not the
  machine's). A route over budget, a route without one and a budget for a gone
  route all fail Build, so a new page is measured on purpose. Raising one is a
  recorded act (`--record-budget`, the rewritten file in the pull request and a
  line saying what grew); the headroom is a constant the unit test pins.
- **The list view is a second face of the same editor, not a second editor.**
  It reads the live store and calls the canvas's own handlers (the arrow's
  picker, the edge removal with its undo toast, the order move, the sheet, the
  interview targets), so it cannot drift from the canvas in what it saves.
  The canvas stays mounted while the list shows (it is the map the list acts
  on), out of sight and out of the tab order. The free map's spatial position
  has no list equivalent beyond Arrange, which is in the toolbar: a position
  is a picture, not a fact. Actions that already had a keyboard path (the add
  picker, "What happens between…", the pending list's accept, History, Export)
  stay where they are.
- **History is paged, not capped.** It listed the newest 200 and said older
  ones were "not listed", so the 201st save made version 1 unreachable from the
  page. A page is 50 (`SNAPSHOT_PAGE_SIZE`) below a `before` version, reading
  one more to know whether another page exists.
- **A restore with unsaved edits saves them first** (issue #45, item 2), rather
  than warning and discarding: what the author did is kept as a version of its
  own and the restore names the version that save reached. The confirmation
  says so; a save that fails stops the restore and says why.
- **A snapshot names the map's current version, for every role** (#45, item 1).
  No product path writes any other (each moves the version, then writes its
  snapshot), so the trigger refuses the superuser too; the one test that wrote
  the snapshot before the version now writes them in the product's order. It
  reads the map `FOR SHARE`, so an insert racing a save compares with the
  committed version.
- **One setting for the cascade marker** (#45, item 5). The value was
  transaction-local, but PostgreSQL keeps every custom setting's name for the
  backend's life, so a pooled connection gathered one per map it ever
  cascaded. The marker now holds `<txid>:,<id>,…,` in one setting, and a map
  that is going (a purge) is not remembered, so a purge does not grow it.
- **A malformed stored note keeps its words** (#45, item 3). In jsdom the note
  did not take the canvas down — `createShapes` threw and the restore skipped
  it — but its text was silently lost; in a browser the throw can come later,
  at measurement. Each `richText` is now rendered once before it goes in; one
  that cannot be is replaced by its text leaves as plain rich text, and a
  shape whose geometry still throws is removed again.
- **The plain-text sanitiser parses before it decodes, and keeps an unclosed
  `<`** (#45, item 4). Two defects, one cause: decoding first turned the text
  `a&lt;b` beside real markup into a tag of its own, and the parser dropped an
  unclosed tag with every word after it. A `<` with no `>` after it (or a `<!--`
  with no `-->`) is handed to the parser as text. What a browser would read as
  markup (`a<b and b>c`) is still stripped; a space after `<` keeps it text.
  The result is idempotent, so the bundle's byte-identical round trip holds
  (values written before stay as they were: nothing is rewritten). Decoding to
  a fixed point stays, so an entity typed as text (`&amp;lt;`) still reads as
  what it encodes: a single decode would not be idempotent and would let an
  encoded tag through one layer down.
- **The D1 guard reads what a hide would need.** The watermark is a
  `div.tl-watermark_SEE-LICENSE[data-debug][data-mobile]` with a button linking
  to tldraw; besides its class, the guard refuses its suffix, its attributes,
  a class substring selector aimed at it, a link selector to tldraw, a key
  under any spelling and, in a stylesheet, the word itself, and re-reads the
  installed tldraw so a release that renames them is seen. The E2E map spec
  still sees the watermark drawn.

## Owner

- `sanitizePlainText` still reads `a<b and b>c` as markup, as a browser would;
  keeping it would mean storing a tag. A space after `<` keeps it text.
- The bundle budget's first numbers were recorded from this half's build alone.
  They were recorded again on the final merged tree (both halves, main and the
  owner's two amendments to D25), after its build, with
  `node scripts/check-build.js --no-build --record-budget`. The merged tree was
  inside the first budget already; the re-record moved every route by under
  1 % (the interview pages a little down, the map, element and kitchen-sink
  pages a little up), and `scripts/bundle-budget.json` is that file.
