                     a round now opens only if the budget also takes its reconcile (nextRoundTokens)
  rephrase           409 TOKEN_BUDGET / WORKSPACE_CEILING before the call                    tests added

LATENCY (item 4)     counted work, not a wall clock (tests/integration/interview-latency.test.ts)
  started, planned   before any model call
  first draft        after exactly ONE generation call of several, within 3 transactions
  stream slots       src/lib/http/stream-capacity.ts (inflect's, per workspace): 4 a workspace, 32 a process
                     interview round streams and research progress streams; released however the stream ends,
                     after the run settles (a cancelled run is still cutting its call)

FAILURE (item 5)     timeout · invalid twice · outage → interview PAUSED (next round resumes), reconcile FAILED
                     (re-run), research FAILED (re-dispatch); every code worded in plain English

EVALUATION (item 7)  every product prompt and pack: a version, a CONTENT hash, a passing record
  promptContentHash  system, task, version, tier, budgets, guard mode, the JSON schema 2.1 sends
  records            pack, reconcile, research and (new) rephrase records carry `promptHash`; the gates refuse a
                     mismatch (PROMPT_HASH_MISMATCH / PROMPT_CHANGED); tests/guards/evaluation-records-current
                     recomputes every hash and fails CI on a changed prompt or pack without a re-run, and on an
                     exported definePrompt template no record evaluates
  rephrase           its own set (rephrase.json), record, D11 gate (503 REPHRASE_NOT_EVALUATED in production)
  judge              src/lib/evals/judge.ts: the model judge (Evals workflow, --judge) and a structural fallback;
                     a report beside the records, never a gate; no pass bar yet
  verdicts           shared by every module graph of the process (src/lib/process-shared-cache.ts)

## Decisions

- **Reconcile counts against the session's budget, and the round leaves room
  for it.** Every model feature must stop at its budget, and reconcile is a
  per-session call. A session that cannot take a reconcile call ends that run
  REFUSED `TOKEN_BUDGET` (nothing sent, the answers kept, worded to say so).
  So that the last round's answers are not starved by the questions, a round
  is opened only when the budget can take its generation calls AND its
  reconcile (`nextRoundTokens`); `tokenBudgetFor` already gave every round
  both shares. A round with nothing answered still ends NOTHING_TO_RECONCILE.
- **Latency is counted, not timed.** The 3-second p95 is a property of the
  provider's first call and of what the request does around it. What the
  request does is countable and deterministic: the first event and the targets
  before any call, the first question after one call of several, three
  transactions. A wall-clock assertion here would measure CI's machine. The
  real-model time to first token is the Evals workflow's to observe.
- **Stream capacity is in-process, per workspace and global**, as inflect's is;
  refused 429 `STREAM_CAPACITY` naming the binding bound, before the run
  starts. The interview stream releases its slot only when the run has settled
  AND the stream is torn down: cancellation aborts the model call, and the
  slot stays held until the call is actually cut, so a client cannot free a
  slot faster than the server frees the work. The shutdown cut inflect carries
  is not: Inkquisitor's shutdown runs after Next's HTTP drain.
- **The cost-aware rate limit counts model calls, per workspace**: one unit per
  generation call a round will make, one for a rephrase, the gather's requests
  plus two for a research dispatch, 40 a minute. In-process like the mutation
  tier, off where every tier is off. Reconcile is not charged: one call per
  closed round, bounded by the rounds the limit already counted.
- **Lost spend is charged, not forgotten (issue #30, item 9).** An expired
  reservation is a call whose process died; its worst case is now added to its
  month when the next reservation sweeps it (logged
  `ai.reservation_abandoned`), and expiry is judged by PostgreSQL's `now()`.
  Over-charging a call that died before it was sent is the price of never
  under-counting one that was. A reconcile against the provider's usage
  report is not built: it needs the Admin API and an admin key (owner).
- **A cut-off stream is charged its unseen output at the bound (issue #30, item
  10).** Generation runs on until the provider sees the disconnect, and
  thinking is billed but not streamed (display omitted), so the reported output
  count understates the bill. The unseen output is charged at `max_tokens` and
  marked `costEstimated`; never above the reservation.
- **A prompt's content is hashed into its record.** A version is a promise a
  person keeps; the hash is the check. The guard recomputes every hash and
  every pack's content and set hash, replays every record, and requires every
  exported `definePrompt` template to be named with its evaluation (the judge's
  prompt is listed as not a product prompt). CI therefore fails on a changed
  prompt or pack without a re-run, before production would refuse it at mount.
- **"Ask me this differently" gets D11 like reconcile.** Its prompt now has a
  set, a structural record and a gate; production refuses it 503
  `REPHRASE_NOT_EVALUATED` (nothing written, the question still answerable)
  until a real-model record lands from the Evals workflow (input `rephrase`).
  Development, test and D13's loopback stub server accept the structural one.
- **The judge grades only at evaluation time.** `JUDGE_PROMPT` runs through
  2.1's `callStructured` in the Evals workflow's throwaway workspace (budget,
  ledger and ceiling apply), over the questions a run recorded, once per
  behaviour each case lists as ungraded; the structural judge (a word list for
  leading phrases, framework names, demeaning words, prose length) is the
  development fallback and says NOT_JUDGED for tone and story content. Its
  report sits beside the records; `JUDGE_PASS_BAR` is `null` and the report
  says `NO_BAR_SET` until real-model evidence argues a bar. A guard keeps every
  product module off it.
- **Verdicts are shared through `globalThis`, keyed by content**, rather than
  precomputed at build time: a build-time verdict file would be a second copy
  of the gate's answer to keep in step, while a process-wide map makes the
  start-up warm-up (instrumentation) the very cache the routes read. The key
  is every hash the verdict depends on (the pack's text, set and parsed record,
  the registry's packs), never an object's identity.
- **An unpinned 2.2 session ends, once.** It can never be pinned, so it is
  STOPPED (`PACK_CHANGED`, problem `PACK_NOT_PINNED`); a retry meets an ended
  interview (409) and writes nothing. A pinned session whose pack changed stays
  PAUSED (a restored file resumes it), and a retry while it is still changed
  writes nothing. The page shows an unpinned session as ended, never
  "Continue".
- **Cosine thresholds are per embedding revision**, the operator's entry
  first, then a reviewed row, then 2.2's uncalibrated 0.9 / 0.97. The table is
  empty: calibration needs the production model.
- **A changed field type on re-import (issue #27, item 8)**: coerce where
  nothing is lost (a string into a list, plain text into rich text, a scale's
  digits), refuse `FIELD_TYPE_CHANGED` naming the field otherwise (rich text
  into plain, several items into one value, words into a number). A value in
  its current shape is untouched, so export → import stays byte-identical.
- **The vector store refuses a write outside READ COMMITTED** (issue #23, item
  3: the first-write lock relies on a fresh snapshot after it), and takes ONE
  first-write lock per workspace instead of one per revision, so two
  transactions writing two new revisions in opposite orders cannot deadlock.
  The readiness probe resolves the table by `search_path`, as every statement
  does (item 5), instead of naming `public`.
- **Docker Hub through a mirror (issue #23, item 4).** Every buildx builder in
  CI lists `mirror.gcr.io` as docker.io's mirror, and Redis runs from it; the
  Actions cache still holds the built layers. Not verifiable from a sandbox:
  the first CI run on the branch shows it.
- **The SDK moved to 1.11.0 (issue #30, item 11)** after reading the 1.9–1.11
  changelog: the API version is unchanged (`2026-10-21`), the transform now
  drops `$schema` itself (2.1 already did), the lenient streamed-tool-input
  parser now rejects non-JSON (stricter, on the single-tool path only). The
  messages-only middleware's suite passes unchanged.
- **The auth spec's cold start (issue #36, item 8), measured.** Readiness
  (`/api/health`) waits only for the instrumentation hook; `next start` loads
  each route's chunk on its first request (the sign-up page: 226 ms cold, 17 ms
  warm). The larger share is the sign-up's own work, which no warm-up removes:
  two bcrypt operations at cost 12 (about 0.27 s each), the workspace's data
  key, NextAuth's round trips and the first render of the workspace page — a
  whole sign-up spec runs 4.6–5.2 s with two workers and three servers on this
  machine, so its sign-up step against a 5 s expectation was a coin toss on a
  loaded runner. 2.5's 20 s sign-up budget covers the work; a Playwright global
  setup now requests every public route the first specs hit, on both servers,
  so the cold-route share is never paid on the clock. Nothing retries locally
  (CI's existing `retries: 2` is untouched).
- **The real-author trial is deferred (D16)** to an owner-run closed beta
  before public launch, recorded as a Phase 7 launch gate; Phase 3 proceeds.
