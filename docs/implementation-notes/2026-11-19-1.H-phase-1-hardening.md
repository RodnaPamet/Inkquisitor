# 2026-11-19 — 1.H Phase 1 hardening

Closes Phase 1 (the book bible): the roadmap's seven items, and the filed
issues that fall in Phase 1 (#17, #18, #19, #20, #27 items 1, 2, 4–7).

## Design

### 1. Sanitising every author-text write

The 1.1 guard (`tests/guards/encrypted-field-sanitiser-coverage.test.ts`)
already proved every encrypted field's classified write methods are called
only beside its sanitiser. It could not see a write method missing from the
classification: a `setNote` added to `BibleRelationRepository` would have
written the note with no rule watching it. Rule 5 closes that: every method of
a classified repository that writes the model through Prisma is either listed
in the field's `writeMethods` or writes a literal `data` object that does not
name the field (`softDelete`, `restore`, `touch`); data the guard cannot read
fails. Every rich-text write was re-checked: field values (`normaliseFieldValue`
→ `sanitizeRichTextHtml`), the concept note, restores and imports all go
through it.

### 2. Two writers: the optimistic version check

```
page loads element at vN ──► every save sends baseVersion = vN (PATCH, PUT …/fields, restore)
server: lock(element) ─► latest == baseVersion ? save, answer vN+1 : 409 VERSION_CONFLICT { currentVersion }
client on 409: hold the batch, stop sending, show the notice ─┬─ Keep my edits ─► re-base on currentVersion, send
                                                              └─ Reload their version ─► drop held edits, re-read, re-seed
```

`assertBaseVersion` (`bible-common.ts`) runs under the per-element advisory
lock, so the latest number cannot move between the check and the save's own
version; a refused save writes nothing (no field, column, version or audit
row). `baseVersion` is optional for a writer that does not track versions.
`useElementAutosave` sends it on every request, takes each answer's version,
and on a conflict holds every edit (a new edit queues but is not sent) until
the author chooses. A restore sends the base too, and the page re-bases on the
version the restore wrote (the 1.2 review's finding).

### 3. Append-only history

The 1.1 trigger (`bible_entry_version_append_only`) stands unchanged. 1.H adds
its counterpart one table up: `book_delete_only_when_purge_due` refuses, for
every role, deleting a `Book` row that is live or deleted less than 30 days
ago, except as its workspace's cascade. A version therefore disappears only
with its book, and a book only through its purge.

### 4. Indexes and bounded reads

- `tests/guards/schema-index-coverage.test.ts`, ported from inflect: every
  workspace model leads an index with `workspaceId`; every foreign key is
  indexed; each list query's index is curated and asserted; every model a
  `findMany`/`groupBy` reads must be triaged. New indexes:
  `Book(workspaceId, deletedAt)`, `Book(deletedAt)`, and
  `BibleElement(workspaceId, bookId, kind, name)` replacing its prefix.
- `tests/guards/find-many-bounded.test.ts`: every `findMany` under `src/`
  passes a `take` (AST-checked), or says why not.
- Capped reads take one more than the cap and say so: the books list
  (`truncated`), an element's relations (`relationsTruncated`), the element
  list (`nextCursor`) — #18.

### 5. Accessibility

`tests/e2e/bible-a11y.spec.ts` runs axe (WCAG 2.1 A/AA, `@axe-core/playwright`)
on the books list, the board, both element tabs, the create and delete
dialogs and Recently deleted, and walks create, edit, relate and restore by
keyboard alone. Found and fixed: hint text in `--content-subtle` on cards
failed contrast (now `--content-muted`); the detail tabs had no arrow keys
(now one tab stop with roving `tabIndex`, arrows/Home/End); the identity pill
and account button failed label-in-name because the avatar's initials were
DOM text (now painted from `data-initials`).

### 6. Load

`tests/integration/bible-load.test.ts` seeds through `createMany` inside the
workspace context (sealed by the encryption extension) and times exactly what
each page reads (`usecases/bible-pages.ts`, which the pages call). CI runs 400
elements / 4,000 versions; `npm run test:load` runs 2,000 / 20,000.

The board no longer lists every element: per kind it reads the count and the
filled fields by aggregate (`groupBy`, a `GROUP BY kind, key` over field keys)
and the first 25 entries of every kind in ONE window query
(`firstPerKind`), with "Show more" paging the rest by cursor. The element page
no longer reads the book's elements for the relation picker, which searches the
server as the author types (`kinds`, `q`). List rows carry no encrypted column,
so a list decrypts nothing.

### 7. Soft delete and the 30-day purge

```
OWNER: Delete book ─ export first ─ type title ─► deletedAt = now ── hidden, every route 404
                                                    │  ≤ 30 days: Recently deleted ─► Restore (whole)
                                                    └─ > 30 days: daily book-purge job ─► DELETE book
                                                          (cascade: elements, fields, relations, versions, vectors; BOOK_PURGED audit)
```

`books.delete` (OWNER only) deletes, lists and restores. The purge finds due
books across workspaces through one row-level-security bypass
(`book-purge-discovery`, ids only), then purges each in its own workspace's
context as the system, re-checking under a row lock so a book restored after
it was found is left alone.

PgBouncer), 30 timed runs after 3 warm-ups. "Before" is the 1.3 code on the
same seeded data.

| 2,000 elements, 20,000 versions | before p50 / p95 | after p50 / p95 |
|---|---|---|
| books list | 2.4 / 3.4 | 2.4 / 3.5 |
| book page | 41.5 / 60.0 (showed 500 of 2,000) | 47.2 / 61.6 (counts all 2,000) |
| element list | 39.6 / 50.9 (500 rows, cut silently) | 15.4 / 19.3 (a page of 100) |
| picker search | — (the page listed 500) | 10.2 / 13.1 |
| element page | 43.8 / 66.7 | 11.9 / 21.0 |

At the CI size (400 / 4,000) after: books list 2.3 / 3.5, book page 26.5 /
32.8, element list 11.8 / 14.5, picker 3.8 / 5.9, element page 11.8 / 16.0.

Whole pages over HTTP against `next start` (signed in, 2,000 / 20,000), ms and
response size:

| page | before p50 / p95, size | after p50 / p95, size |
|---|---|---|
| books list | 33 / 51, 53 KiB | 26 / 44, 57 KiB |
| book page | 70 / 96, 388 KiB (500 entries) | 66 / 82, 312 KiB (25 a kind, all counted) |
| element page | 57 / 78, 150 KiB | 38 / 51, 109 KiB |
| element list API | 44 / 49, 133 KiB | 19 / 33, 23 KiB |

Nothing measured exceeded 300 ms at p95 before or after: the 300 ms bound is
held by the test at both sizes. What 1.H fixed at size was correctness (#18:
the board and picker stopped at 500 elements and said nothing) and the
element page's cost, which grew with the book (it read every element for the
picker); the book page's server time now stays flat as kinds fill, because it
reads at most 25 entries a kind. With 50 a kind the book page measured 141 /
161 ms (15 queries, one per kind) and then 58 / 71 ms in one window query.

## Decisions

- **Who deletes a book: the OWNER only, through `books.delete`.** A book is
  the largest unit of the author's work, and deleting one is a decision about
  the workspace, not an edit. An EDITOR keeps deleting elements (the undo
  toast) and loses only this. The same key lists and restores, so the person
  who can undo a deletion is the person who could make it.
- **Soft delete, then a purge, held by the database.** `deletedAt` hides the
  book at once (every usecase starts from `requireBook`, whose read filters
  live books, and `BibleElementRepository.find` filters by the live book too),
  and the trigger makes the window real for every writer. The import usecases
  check the book before reading or scanning the upload, so a deleted book's
  import routes are 404s too (`book-delete-purge.test.ts` calls every route).
- **Restore within the window only.** Past 30 days a deleted book is not
  listed and not restorable even before the purge reaches it: what the dialog
  promised is the date, and the purge may run any time after it.
- **The export comes first, not last.** The dialog opens on the two exports;
  a deleted book is not exportable (its routes 404), so the moment to keep a
  copy is before the delete. Typed confirmation (the book's title, exactly)
  rather than the undo toast: CLAUDE.md's convention for a top-level entity.
- **A stale save is refused even when it would change nothing.** Its answer
  would otherwise re-base the writer on a version their screen does not show.
- **#27 item 1: lower the bound, not a worker job.** A job's payload is stored
  in Redis in plain text and may not carry author text, and storage does not
  seal (the 1.3 decision not to store uploads), so moving the parse to the
  worker means a new encrypted staging store. Measuring first changed the
  question: the YAML library's own duplicate-key check was QUADRATIC in a
  mapping's size (20,000 keys 4.9 s, 100,000 keys two minutes), far worse than
  the ~2 µs a character #27 assumed. With duplicates found by a set per
  mapping the densest YAML parses at ~1.4 µs a character, and literal block
  scalars (what an export writes) at ~0.01 µs. So: linear duplicates; the file
  bound 8 → 2 MiB and the total 64 → 24 MiB (an average of 12 KiB for each of
  2,000 elements, two to four times a full CHARACTER file); and the parse
  yields to the event loop after every file, so an import holds the process
  for one file's parse (~3 s worst case) rather than the bundle's (~35 s worst
  case at the new total). The export refuses (`EXPORT_TOO_LARGE`) what the
  lower bound would refuse, so every export still imports back.
- **#27 item 4: the key alone names a relation type, and that is now checked.**
  The templates' "no earlier target kind" rule already made two declarations
  of one key unable to meet between the same two elements; `loadTemplates`
  now refuses a template set where they could (`relationLookupCollisions`),
  and `findPair` matches symmetric rows only.
- **#19: the toggle reports through `onModeChange`.** The 1.2 guard in
  `FieldEditor` (a switch saves nothing, and coming back without typing
  restores the field's own HTML) is kept, now driven by the new callback.
  `prose-invert` named a typography plugin that is not installed; the content
  takes its colours from the theme tokens, which hold AA in both themes.
- **#20: restore stores null.** The history labels a restore from
  `restoredFromVersion` through next-intl; an author's own summary still shows
  beside it.
- **#17: strip, don't refuse.** Sign-up names lose control characters
  (`cleanLine`) as the bible's plain text does; a name of only controls falls
  back to the default.
- **Initials are painted, not written.** The avatar was already `aria-hidden`,
  but axe's label-in-name rule (WCAG 2.5.3) reads visible text regardless; the
  glyphs now come from `data-initials` through `::before`.
- **The load test's "before" was measured, not assumed:** the 1.3 tree,
  exported with `git archive`, against the same seeded database.

Left open, not Phase 1: #23 (vector rebuild, 2.1/4.1), #24 (a Unicode PDF
font), #27 item 3 (an owner decision) and item 8 (a template field type
migration rule).
