# 2026-11-20 — 2.6 Research agent and the Research page (D9)

**Commit:** uncommitted (branch `wip/2.6`; `main` merged in at `d6a0396`, 2.5's
PR #38, whose helpers are reused rather than copied)

An author writes a research brief: a question, why they ask it, the bible
elements it is for, optional URLs and text files, and a depth. A worker job
runs it: the model searches and fetches the web through Anthropic's server
tools, drafts findings that quote their sources, and proposes bible changes
drawn from those findings. Code refuses every finding whose quote it cannot
find in the source and every proposal that breaks a rule; the author reviews
the rest with 2.5's review UI. Nothing reaches the bible otherwise.

## Design

### Query egress, and its honest limits

D9 says research queries are written from the brief and carry no manuscript or
bible text. Three places hold it (`src/lib/research/query-egress.ts`):

1. **The brief is a gate.** Its question, purpose and URLs are checked at
   creation and again at dispatch against the book's stored text: a run of 4
   consecutive words, 2 of them content words, in common is a quotation and
   refused `BRIEF_QUOTES_BIBLE` (naming the part). A character's name alone is
   not: the brief may name its subject. A secret shape (2.1's egress scanner)
   is refused too.
2. **The gather request carries the brief and nothing else of the book.** The
   model writing the queries holds no bible or manuscript text to quote. This
   is the guarantee.
3. **Each query and fetch URL is checked as the stream completes it** (the
   `contentBlock` event): a refusal aborts the stream and ends the run
   `QUERY_REFUSED`. Anthropic runs a server tool itself before the client sees
   the block, and the API has no approve-before-run hook, so this is a
   **tripwire**: it records and stops, it cannot unsend. A URL's host is not
   checked (where a page lives is not a quotation), only its path, query and
   fragment; URLs written in the bible are left out of the index, or every
   page of a site a kept note cites would be refused.

Limits stated plainly: the brief's own words reach the search provider (that
is their purpose); a paraphrase of the bible in the brief passes the shingle
check; the shingle check over a book past 4M characters refuses everything
(`INDEX_INCOMPLETE`) rather than vouch unseen. Client-side search, where every
query could be approved before it leaves, would need a search API of our own,
i.e. a new sub-processor: an owner decision.

### Zero retention

`web_search_20260209` / `web_fetch_20260209` are ZDR-eligible except on
Covered Models when dynamic filtering is off; the middleware refuses a web
tool without `allowed_callers: ["direct"]`. Publishers may keep the URLs
fetched. `docs/sub-processors.md` records this and the privacy-page draft.

## Decisions

- **Server tools, not client tools.** The roadmap names Anthropic's web
  search; a client-side search would need a provider of our own. The loop is
  its own module beside `callStructured` because a server-tool turn is not a
  structured output: it is a conversation the provider continues
  (`pause_turn`), with no output schema.
- **One AiCallLog row per request**, each reserved at its own worst case:
  ten server-loop iterations, each searching up to the remaining cap at an
  assumed 30k tokens a search (`SEARCH_RESULT_TOKENS_BOUND`) and fetching at
  `FETCH_MAX_CONTENT_TOKENS`, plus the search fee. The search bound is an
  assumption, not a documented limit (owner item).
- **Only fetched pages are citable.** Search results come back with their text
  encrypted by the provider, so a span from one cannot be verified. The
  findings step reads fetched pages and attached files; each quote must occur
  in exactly the text it was shown, after the same folding, at least 20
  characters.
- **Page text is not stored.** Only verified spans (and the URL, title,
  retrieval time). An attached file's text is stored, encrypted, because the
  author gave it. Storing a page hash for later integrity checks is left for
  2.H.
- **Markup in a drafted claim refuses the finding** on the raw value; it is
  never sanitised and kept, because a page that injects markup is telling the
  model something.
- **2.5's helpers, not copies**: `groundingForm`, `addressesTheProduct` /
  `flagsOf` (D14), `bookHoldsElementName`, `effectiveRunState` with
  `CLAIM_EXPIRED` (`STALE_RUN_MS`, 30 minutes: a run can take longer than a
  reconcile).
- **A missing brief is a 404 first.** Dispatch and attach read the brief (and
  so the live book) before saying anything about the deployment (503
  AI_UNAVAILABLE / RESEARCH_NOT_EVALUATED) or scanning the file, so every
  route under a deleted book answers 404 (`book-delete-purge.test.ts`); both
  read it again under the brief's lock.
- **The worker re-checks the requester.** A job runs after the request that
  made it; if the requester lost `bible.edit` meanwhile the run is REFUSED.
- **The job runs once** (`attempts: 1`): a retry would re-search and re-spend;
  a failed run is dispatched again by the author.
- **Proposals are written against the values read**, and only persisted
  (UPDATE) while the stored value is unchanged since that read; acceptance
  re-checks under the element's lock as 2.5 does.
- **Evaluation**: structural records come from a deterministic researcher over
  the fixed fake web; the model record runs FINDINGS and FIT over the same
  pages (no live search in evals: owner item). D11 through
  `deploymentPackRecordMode()`, so the D13 stub server mounts structural.
- **E2E needs the worker**: Playwright starts it from source as a third
  webServer, waiting on its "listening for jobs" line.
